# eval 硬规矩

这些是写 eval 代码时必须遵守的约束。字段含义、函数签名一类的参考资料在
`scripts/eval/cluster-to-brief/CONTRACTS.md`，需要时再读，不要整份背下来。

## 判据不得带架构假设

判据只描述**输出的性质**，不描述实现结构。

反例（真实教训）：v1→v6 那一轮里判据写成「必须拆 ≥2 块」，架构一改判据就失效，整批读数只能作废。

同理，eval 只依赖 dataset 与输出契约，不依赖链路内部。solver 内部拆几步、调几次模型、跑在哪，eval 一律不管。

## sample 是视图，不是数据

同一份 dataset 里「一个簇」和「一天的全部文章」都可以是一个 sample，取决于要判什么。
所以切分不落盘、不进清单，按需实例化（`sampleView`）。

把粒度写死进清单等于把「判什么」焊在输入上，换判法要重做数据。

## 标注挂在输入上

target 要描述输入的性质（「这两篇讲同一个事件」），不要描述某个系统的输出。
挂在输入上的标注换架构不失效，这是金标能长期留存的唯一条件。

## 金标必须能自解释

一份金标是一个包，缺任何一件都不可用：

| | 缺了会怎样 |
|---|---|
| 标签 | — |
| 证据快照 | 判定无法复现 |
| rubric（标注规范） | 标签无法解释 |
| 出处（谁标的、标的哪版输出、参照系是什么） | 无法判断还适不适用 |

**rubric 不许跨目录引用别的 harness 的 rubric。** 那两个目录的存亡由各自的 harness 决定，
引用随时会断——2026-09-22 清理时 `intel-grounding/rubric.md` 就因为引用
`faithfulness/rubric.md` 而差点变成一批无法解释的标签。宁可复制几十行文字。

### 清单必填两个字段

- **`targetOf`**：`product`（考被测系统）或 `judge`（考判官本身）。
  两者的 `{input, target}` 形状一样，差别只在 solver 槽里坐的是谁。缺了它，没有任何东西
  拦得住你把判官成绩当产品成绩报——而一份判官金标里的 claim 是旧架构写出来的句子，
  不管接到哪个 task 上都不代表当前系统会产出什么。
- **`labelBalance`**：target 各取值的条数。依据是 Hamel Husain 对 LLM-as-judge 的警告——
  agreement / κ 是陷阱指标，样本不平衡时判官把少数类全判错也能拿高一致率，
  而少数类恰恰是你在乎的失败。由产出脚本数出来写入，不靠人手填。

### 证据快照要标明参照系类型

- `raw_source`：外部素材（如原始 RSS 文章）。换架构仍然有效，长期保留。
- `retired_intermediate`：系统的中间产物。架构一变即死——**做的时候就要知道它是消耗品**，
  用完把读数蒸馏进 `docs/knowledge/`，语料不必留。

有些判定天然只能用中间产物当参照系（「brief 忠不忠于情报报告」没有别的问法），
所以不禁止，但不要指望它复活。

## 判官上线前必须和人对齐

未经校准的判官会返回一个看起来正常的数字，光看分不出它是认真判的还是瞎猜的。

- 实测：qwen-max 在 intel-grounding 上 κ=0.407 FAIL，deepseek-v3 同样 FAIL。真信了它，
  那批读数全是噪声。
- 同一个判官在不同通道表现可以差很远：忠实度门的事实通道 κ=0.76 可用，分析通道 κ=0.27 不可用。
  **限定判官只判它能对齐的那类断言**，比换更强的模型便宜得多。
- 量 TPR / TNR，不要只看 agreement（见上面 `labelBalance` 那条）。
- 样本量：低于 60 条置信区间太宽，验了等于没验。

**能用代码确定性判定的，一律不要上 LLM 判官**（样板：`scrape-quality` 直接 import 生产的
`extraction-quality.ts` 函数，零 LLM、零网络）。没有判官就没有判官要验。

## runner 与臂的职责边界

数据来源知识和运行策略归 runner，求解归臂。

**判据**：臂的源码里搜不到 `dataset` / `fixtures` / `DEV` / `loadDataset` / `recordConsumption` /
`loadCluster` —— 搜得到就说明数据来源知识又漏回臂里了。

## holdout 卫生

- `split` 是整份 dataset 的属性，不是样本的属性（对齐 Inspect 的口径：split 是「载入哪一份数据集」）。
- `consumed` 只增不改。用过的 dataset 对该臂不再是未见过的数据。
- 跑过 test 集就不再是 heldout，别拿它反复调参。

## 拿历史数据当 heldout 前先验输入形状

历史数据可能来自已经改掉的架构。2026-09 连续两次踩：09-14 是旧架构（一簇切多块，clusterId 重复）、
09-16 是簇判定塌了那五天（过滤后平均篇数仍是 1.7 倍）。两次都是用户发现的。

## 金标是资产，不是产物

人工标注语料入 git，和代码一起版本化（OpenAI Evals 的先例：`registry/data/` 进 git）。

这条不是洁癖：2026-09-12 有一批 94 条人工金标被「调研产物不入 git」的落位规则连带扫走，
而它标定出来的归并阈值 0.94 至今还在生产里跑着，**没有可复现的标定依据**。
