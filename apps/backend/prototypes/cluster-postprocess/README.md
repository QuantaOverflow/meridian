# 聚类后处理层原型（用完即弃）

**问题**：聚类阈值调严之后纯度涨、事件被切碎。设想补一层后处理——用簇质心余弦筛出「疑似被切开」的簇对，交给 LLM 成对判定，判 same 的合回去；同时把「只有题材没有事」的题材袋处理掉。**这一层的判决与聚合规则对不对？**

纸上想不清楚的四点：

1. 成对判定会传递（A-B 合、B-C 合，但 A 与 C 未必像）。全链约束够不够挡住链式雪球？会不会误挡该合的？
2. `unknown`（判官拿不准）默认不合，代价多大？
3. 合并后的大小守卫卡几篇？卡太紧会挡住真·大事件（尼泊尔洪灾 71 篇）。
4. 题材袋该丢、该拆、还是只标记？

## 跑

```bash
cd apps/backend/prototypes/cluster-postprocess
pnpm run tui                    # F2 窗口、凝聚 t=0.08
pnpm run tui -- F1 0.10         # 换窗口 / 换阈值
pnpm run headless               # 不交互：金标当判官，扫守卫参数，看上限
```

用的是真实 fixture（`../dedup-band/fixture-F{1,2}.jsonl`）+ 真实人读金标，**全内存、不写任何东西**。

你在 TUI 里扮演那个还没建的 LLM 判官：逐对看两簇标题，按 `[s]` 同一件事 / `[d]` 不同 / `[u]` 拿不准，上方指标立刻重算。`[o]` 让金标代判全部 = 判官做到完美时的上限。

## 已经跑出来的（金标代判 = 完美判官上限，候选阈值 0.90 / 全链开 / 守卫 60 篇）

```
                        交付率  纯度   题材袋  跨簇   完整
F2 t=0.08 后处理前       0.928  0.875  0.129  1.19  0.901
F2 t=0.08 合并后         0.928  0.859  0.147  1.03  0.927
F2 t=0.10 后处理前       0.960  0.804  0.178  1.08  0.951
F2 t=0.10 合并后         0.960  0.796  0.186  1.02  0.965
F1 t=0.08 后处理前       0.821  0.936  0.054  1.13  0.935
F1 t=0.08 合并后         0.821  0.929  0.059  1.01  0.947
F1 t=0.10 后处理前       0.915  0.864  0.099  1.10  0.970
F1 t=0.10 合并后         0.915  0.859  0.105  1.04  0.977
```

三条读数，四个配置一致：

- **合并层只治碎，不治漏**。跨簇 1.19 → 1.03、完整 0.901 → 0.927，但**交付率一动不动**。机制：交付要求某个簇里有 ≥2 篇同事件，而掉出去的碎片多是单篇、根本不构成簇，簇级合并看不见它们。要救交付得做**篇级挂靠**，不是簇级合并。
- **纯度与题材袋率会轻微变差**（0.875 → 0.859 / 0.129 → 0.147）。不是合错了，是分母变小：簇数 155 → 136，而题材袋原样留着。
- **全链约束在完美判官下几乎不触发**（链挡 0–5 对），大小守卫在 60 篇会挡掉真该合的（F1 t=0.10 挡 8 对）。传递性到底会不会出事，得用**不完美**的判官才试得出来——那正是手动驾驶要做的事。

## 结论落在哪

验完之后 `logic.ts` 整块可以搬进生产（纯函数、无 I/O）：`buildMergeCandidates` / `applyMerges` / `detectPockets`。`tui.ts` 和 `headless.ts` 是驾驶台，不进生产。
