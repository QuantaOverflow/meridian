# 一簇即一条：聚类换成阈值型凝聚，删掉簇的切分层

2026-09-05／06。取代 ADR 之前散落在 `3_智能简报算法合理性与优化分析报告.md`（已删）里的算法链路描述。

## Context

原链路是 `文章向量化 → UMAP 降维 → HDBSCAN 聚类 → 切分 → 情报分析 → 排序 → 简报合成`，其中「切分」这一层反复换过实现：story-validation 让 LLM 划分整簇（2026-08 前）→ 几何候选组 + 逐组判定（2026-08-20）→ storyline 两段式命名主线 + 逐篇归类（2026-09-03）。

每一次换实现，都是因为**上游给的簇不干净**：一个簇里装着好几件事，所以下游必须有人去切。而切分本身是 LLM 做不好的任务形态——91 篇的簇让模型一次划分，12 轮里只有 1 轮把 id 分对。

2026-09-05 建了两窗人读全覆盖金标（F1 1142 篇 / F2 1252 篇，各三个标注者独立通读，一致性 ARI 0.906–0.98），第一次能直接量「簇有多脏」，也第一次能问：**病是不是在聚类本身**。

## Decision

**换聚类器，然后删掉整个切分层。**

聚类：`384 维 embedding L2 归一化 → 余弦距离矩阵 → average linkage，阈值 0.10，最小 3 篇成簇`。不降维、不做密度聚类。

切分层：删除。每个簇送一次 LLM，同时回答「这簇是不是一件事」与「这件事叫什么」（`/meridian/cluster/judge`），产出直接作为简报里的一条。

两窗产品口径实测（`<3 篇的簇与事件都不计`，打分器 `eval/clustering/product-score.ts`）：

|  | 交付率 | 簇纯度 | 题材袋率 | 跨簇数 | 完整率 |
|---|---|---|---|---|---|
| F1 旧 UMAP+HDBSCAN | 1.000 | 0.408 | 0.273 | 1.04 | 0.992 |
| F1 新凝聚 t=0.10 | 0.943 | **0.913** | **0.000** | 1.14 | 0.949 |
| F2 旧 UMAP+HDBSCAN | 1.000 | 0.354 | 0.286 | 1.03 | 0.993 |
| F2 新凝聚 t=0.10 | 0.934 | **0.864** | **0.072** | 1.09 | 0.918 |

簇纯度翻一倍多，题材袋（只有题材没有事的凑堆簇）基本清零。交付率掉的 6 个百分点全是 2 篇的长尾——两窗实测简报前 25 名里 2 篇的簇一个都没有（第 25 名 blockScore 3.40/3.48，而 2 篇 2 源只有 2.38）。

调用量从每期 430+ 次（每篇一次归类）降到约 70 次（每簇一次）。

## Considered Options

**去 UMAP vs 保留降维**。UMAP 保局部近邻不保全局距离，把「真成员离簇心 0.027 / 外来篇 0.149」这个 98% 可分的信号打散成 45.5% 重叠。去掉后副产品是**没有随机性**——同一输入永远同一结果，跨种子稳定性问题消失。

**阈值型凝聚 vs 密度聚类**。HDBSCAN 判局部密度，没有「要多像才算同一件事」的概念，一堆同题材孤篇挤在一起也构成密度区。凝聚认绝对相似度：同事件报道余弦 ≈0.92 以上，同题材不同事 ≈0.85–0.88，阈值卡在中间。

**average vs complete linkage**。complete 要求组内所有对都达标，一件事里写法特别的那篇（只写数字不写主体名的那类）会被踢出去，实测跨簇数 1.20 vs average 的 1.08。

**最小 3 篇 vs 2 篇**。2 篇的簇本来就进不了简报，砍掉不损失会被读到的内容，却带走了大部分题材袋（F2 32→5 个、F1 15→0 个）。剩下的题材袋几乎全是 2–3 篇的边界样本——「两篇报道算不算同一件事」本来就是最没有确定答案的形态。

**删切分层 vs 保留**。保留的前提是「簇不干净」，而簇纯度 0.86–0.91 之后这个前提不成立了。且切分是 LLM 的能力洼地（一次划分 91 篇，12 轮 1 轮对），删掉它同时去掉了一个不稳定源和 360 次调用。

**判定层 NO_EVENT 丢弃 vs 只标记**。选只标记：让 LLM 毙掉整簇 = 簇级硬门的 LLM 版，全有全无；零 LLM 的硬门就这么把 8 篇 NASA 望远镜簇、11 篇阿富汗驱逐簇整个抹掉过。且题材袋在 3 篇截断后只剩 0–5 个、blockScore 全在前 25 之外，丢与不丢对读者没差别。

## Consequences

**一件大事在简报里只占一条。** 以前 storyline 会把 81 篇的洪灾切成几条主线各占一格；现在是一条。好处是块间重复消失（曾出现同一场洪灾在两个簇各自成块、标题逐字相同），代价是大事件不再多占名额，前 25 的覆盖面变了。

**每条只能读 30 篇正文。** `pickSpreadArticles` 的 cap 保留（按时间等距取样、两端锚定）。81 篇的事件因此丢掉 63% 的材料——但 2026-09-05 的实测表明这不损失信息量：`corr(报告时间线条目数, 输入篇数) = −0.015`，10 篇给 9–11 条、81 篇给 12 条。一次调用产出的信息量与输入量无关，是这一层的独立问题（见下条）。

**情报分析层的瓶颈被重新定位。** 原以为是输入太长导致超时（生产曾记录 91 篇 → 300 秒硬失败）。隔离探针实测：`corr(墙钟, 输入token) = +0.014`、`corr(墙钟, 输出token) = +0.848`，全部 81 篇的 prefill 只要约 14 秒。真凶是**输出的复读退化**（30% 的调用冲到 maxTokens 8192 并 `finish_reason=length`），与篇数无关。因此「拆输入降时延」这条路作废，该治的是输出退化与信息利用率。

**残余杂质进写作材料。** 交付簇里约 5.6%（F2）/ 6.8%（F1）的文章不属于主导事件，且集中在持续冲突的大簇吸附相邻子事件（美伊战争簇吸进卡塔尔斡旋、Kharg 岛 AI 视频）。曾试篇级排除（让判定层同时指出哪几篇不属于），精度只有 0.20、误排 74 篇，否掉；靠下游 RARR 接地校验兜。

**判定必须与调用失败分开。** 失败重试一次，仍失败则整簇保留成一块、名字用零 LLM 的主导专名，计数进观测。把失败读成「这簇没有故事」会让一次网络抖动毙掉一条真新闻——这个仓库栽过。

`docker.io`，网络不通时 build 卡死在**读到聚类代码之前**——本 ADR 的算法改动因此从未被生产

要判镜像版本，须看 `wrangler containers info` 的 version 与 LAST MODIFIED。踩坑细节与判断方法见

## 已证伪，别重跑

- **特征工程七臂**（TF-IDF 字段加权、实体 Jaccard 融进距离、时间衰减、题材字段消融、IDF 加权实体、质心剥离、通道分歧门）：它们治的是 UMAP 造成的病，去掉降维后全部归零。
- **四条绕开「纯度 vs 交付」取舍的路**：源特征剥离（同源/跨源余弦中位数只差 0.004，没有可剪的分量）、合并守卫（纯 average 的簇内最大距离最多 0.20，链式合并本来就没发生）、互为近邻约束（纯度 +0.03 但跨簇数 1.08→1.30）、核心-挂靠两段式（落在单阈值前沿之下）。纯度与交付在同一条曲线上，只能选操作点。
- **判定 prompt 的两个方向**：把判据改写成「时间+地点+参与者+动作」四要素合取，两窗一致地把误杀翻 2–3 倍；写进「拿不准偏 EVENT」，题材袋召回塌到 0.11/0.08。
- **簇级合并层**（把被切开的事件合回来）：候选生成零漏（簇质心余弦 ≥0.90，F2 81 对候选覆盖全部 44 对该合的），但完美判官下**只治碎不治漏**——跨簇数 1.19→1.03、完整率 0.901→0.927，交付率一动不动。掉出去的碎片多是单篇、不构成簇，簇级合并看不见它们。原型留在 `apps/backend/prototypes/cluster-postprocess/`。
- **生产环境（无金标）靠几何方法检测「被漏掉的事件」**：在噪声池（未成簇的孤篇）里再跑一次凝聚，≥3 篇成组就当疑似漏报。2026-09-20 实测精度只有 0.05–0.33，没有可用操作点。原因：噪声池里本就是 700 多篇互不相关的孤稿，任何阈值都能在里面凑出假的「疑似漏报组」；且真漏报信号极稀疏（F1 只有 3 个事件被整个漏掉、F2 只有 4 个，全是 3–4 篇的边缘事件），置信区间比要测的效应还宽，测不出稳定结论。细节见[知识节点](../knowledge/nodes/lesson-noise-pool-leak-detection-falsified.md)。
