# ADR 0009：地图首页——`/` 改为最新一期的地球视图，全站界面改英文

- 状态：已采纳，2026-10-04 上线（backend `803a1b54`、Pages `9807a373`）
- 日期：2026-10-04
- 相关：`packages/contracts/src/reader-map.ts`（接口形状）、`apps/backend/src/lib/reader/brief-map.ts`（数据）、
  `apps/frontend/src/pages/index.vue` 与 `src/lib/`（展示与渲染器）；spec 与票在本地 `.scratch/globe-home/`，
  原型在本地 `apps/frontend/prototypes/globe/`（都不入库，本文是它们的入库结论）

## 背景

读者打开站点直接落在最新一期正文上，「今天世界哪里出了事」要逐条读 25 个目录项才拼得出来；地理、话题、
没聚成事件的零散报道、某条是哪个长线事件的最新进展，在阅读页上都看不见。另外站点界面是中文、内容是英文，
同一张卡片两种语言，Chrome 对这种混合页可能不弹翻译。

## 决定

1. **`/` 是最新一期的地图首页**，阅读页留在 `/briefs/:id`。顶部是期号、日期、导语和「Read today's brief」；
   下面是地球 + 右侧面板。每个正文故事是它主要发生国家里的一个点，国家底色是当期文章池按国家的篇数（对数刻度）。
   点国家锁定、点话题筛选；锁定后面板列出该国故事、牵涉该国的外国故事，以及**当天其他报道**（见 `GLOSSARY.md`）。
2. **数据全来自现有数据，不新增模型调用**：文章的 `primary_location`、`topic_tags`，线索（`story_clusters`），
   每期的 brief-v3 写作记录（R2）。backend 加一个只增不改的接口 `GET /reader/briefs/:id/map`，先部署 backend 再部署前端；
   回滚只需切回上一个前端部署。
3. **正文块 ↔ 故事靠簇编号，不靠标题**：brief-v3 记录里每个写成的块带 `clusterId`，与同一 run 的
   `brief_stories.cluster_id` 对上。对不上的块从响应里丢掉并记 error 日志；记录缺失 / 读失败 / 形状不对时
   事件为空、文章统计照常返回并记日志。
4. **归一与展示分两层**：backend 把 `primary_location` 原值归一成 ISO 3166-1 alpha-2（联合国 `UN`），
   只写了地区或组织的计入 `regional`，表里没有的计入 `unmapped` 并记原值；**落点阈值、国家英文名、坐标、底图名、
   话题英文名在前端**（落点：头号国家 ≥30% 标在该国；没有国家到 30% 时，≥10% 的国家两两连线）。
   **连线的第二个国家看 `mentions`**（2026-10-04 改，见下方「连线」一节）：backend 给出成员文章提到各国的比例
   （每篇的地点与关键实体里能归一成国家的各算一次，`Georgia` 这类有歧义的实体名不算），前端在另一国被至少 2/3 的成员提到、
   且不与下一名并列时连线。
   两张表各维护一份，由前端测试 `test/place-tables.test.ts` 锁住「backend 能产出的每个代码前端都有」。
   **2026-10-08 补**：落点规则（阈值与 `place()`）从前端挪到 `packages/contracts/src/placement.ts`，规则本身没改；
   backend 写简报块时用同一份规则算块的落点国家与涉及国家（国家页按它查，见 ADR 0014）。国家名、坐标等展示表仍在前端。
5. **话题从 `topic_tags` 映射到 9 个**（security / tech / economy / justice / society / environment / culture / sports / politics）：
   一个故事要有至少 2/3 的成员文章带某话题的标签才算，最多 2 个；`politics` 只在别的都不沾时兜底
   （Politics / World Affairs 几乎每篇都有）。零散报道按篇计，一篇可计入多个话题。
6. **线索门槛与线索列表页一致**：只给出现在 ≥2 期已发布简报里的线索，`briefCount` / `durationDays` 复用列表页的同一条查询。
7. **当期文章池是事后重建的**：照 workflow 构造时间窗的同一套规则（`article_ids` / `dateFrom`–`dateTo` / `timeRangeDays` / `articleLimit`，
   见 `brief-map.ts` 注释指向的 workflow 位置）从 `brief_runs.params` 还原，用 `runWindowWhere` 同一组过滤。
   接口不声称它等于当时的真实输入。
8. **渲染器是独立模块，接口窄**：页面只给点、连线、底色和话题暗显集合，收回锁定与悬停；绘制、拾取、旋转、缩放、皮肤都在
   `HoloGlobe.client.vue` + `lib/holoGlobe.ts` 里，场景类型在 `lib/globeScene.ts`。本次是 d3 canvas 正交投影，只保留 holo 皮肤；
   以后换 three.js 3D 外观只替换渲染器这两个文件。地球是客户端懒加载组件，顶部和面板服务端渲染，地球没加载出来时文字照常可读。
9. **全站读者界面改英文，中文读者用浏览器翻译**，不做服务端翻译。阅读页、归档、线索页只改文案不改样式；admin 不在范围内。

## 读数

- 块 ↔ 故事：111 期（期内同事件合并前）与 114 期（合并后）都是 25/25 一一对上、无重复簇编号；115 期上线时 21/21。
- 线索落国：线索列表 139 条里 96% 有一个国家占到成员文章过半，所以线索能从现有数据落到地图上，不需要新的 LLM 调用。
- 当期文章池重建：111 期重建出 532 篇，`brief_runs` 记的是 508 篇；115 期 409 篇，分布在 57 个国家。
- 归一化表覆盖：原型按 111 期建的表，到 115 期有 25/409（6%）落不了国（Latvia、Portugal、Kenya、Cuba、Sudan，
  连 Austria 都只有 Vienna 一个别名）。按生产近 30 天全部原值（17,789 篇、约 300 种写法）补成 world-atlas 110m 全部国家 +
  10 个无轮廓小国 / 属地 + 美国各州、英国各郡、地区类值之后，只剩 48 篇（0.3%）是 `string` / `Unknown` / `N/A` 这类无效值。
- 期内同事件合并（`0aec056`）之后，113、114 期 25/25 故事都入选，所以原型里「聚了簇但没进简报」那一层去掉了。

## 连线（2026-10-04 改规则）

上线后发现「Cross-border links」开了也几乎没有线：原规则按成员的**地点**占比，第二国 ≥15% 才连，但一事的报道几乎都填同一个地点——
115 期 21 个故事里 20 个地点 100% 是同一国，唯一一条线（阿联酋–阿曼）两国相邻、又是 0.3 透明度的细虚线，看不见。
第二个国家其实在文章的**关键实体**里（朝鲜导弹的报道地点是韩国、实体里有 North Korea；厄立特里亚断交的地点是埃塞俄比亚、实体里有 Eritrea）。

在 111–115 期 121 个正文故事上量过（逐条判「真跨国 / 说不准 / 强行关联」，判定者 Claude 一人）：

| 门槛（提到该国的成员比例） | 连线 | 真跨国 | 说不准 | 强行关联 |
|---|---|---|---|---|
| ≥1/3 | 50 | 34 | 7 | 9 |
| ≥1/2 | 48 | 34 | 7 | 7 |
| ≥2/3 | 35 | 28 | 5 | 2 |
| **≥2/3，并列不连，Georgia 不算** | **30** | **25** | **5** | **0** |

强行关联的来源：多边事件顺带提到的国家（G7 → 法国、美军撤出伊拉克 → 伊朗）、名人提及（巴西大选 → Trump → 美国）、
两国并列时取错（爱尔兰对以色列的球赛，奥地利与巴勒斯坦并列）、实体 `Georgia` 是美国的州。
「说不准」三类按以下判：两国国家队的比赛算真跨国；遣返目的地算真跨国；**事件的附带地点（航班备降沙特）算勉强**——
这类规则挡不掉，5 期里 3 条，即约 10% 的线是勉强的。代价：并列不连也去掉了 3 条真跨国的线。
没量的：实体里根本没提另一国的跨国事件（漏连）。

## 证伪 / 放弃

- **按标题对块和故事**：原型在 111 期上发现正文块标题与 `brief_stories.title` 小写、统一引号后能 25/25 对上。
  但 `fe51180` / `c008bcb` 之后正文标题由 v6 写作层照正文起名、原样保留大小写，与聚类阶段的故事名会不一样，
  这条路已不成立。改用 v3 记录的 `clusterId`（决定 3）。
- **话题门槛 0.67**：原型写的是 0.67，比 2/3 略高，3 篇里正好 2 篇的故事会被漏掉；改成精确的 2/3。
- **按样本建归一化表**：只按一期数据建的表在下一期就漏 6%；补表要按一段时间的全量原值做，并用测试锁住两表同步。

## 已知局限（上线时接受）

- 约 10% 的连线是事件的附带地点（如备降地），不是两国关系。
- 话题标签有噪声：例如马岛石油争端落在 environment；Conflict & Security 占了近一半文章。
- 国家底色反映的是我们订阅了哪些信源，不是哪里发生了更多事（111 期美国 195/532 篇）。图例写明底色是文章数。
- 浏览器翻译会改写 DOM，可能和 Vue 的更新冲突。上线前用户在本地开 Chrome 整页翻译后点国家、切话题，页面没坏；
  但这是一次人工检查，不是持续保证。微信内置浏览器没有翻译——读者若主要从微信来，要重新考虑服务端翻译。
- 约 0.2% 的文章 `primary_location` 是字面量 `string`（文章分析把 schema 里的类型名当答案），属生成链路的问题，未处理。

## 没做 / 以后再说

- 美国这类故事多的国家把点展开成单条故事；故事级或国家以下的地理定位。
- 往期地图、线索的地图视图；阅读页、归档、线索页的 holo 外观。
- 服务端翻译成中文；让写作层在生成时直接给话题。
- three.js 3D 外观（只换渲染器模块，见决定 8）。
- 没在真机上验过触屏拖动，也没验过系统「减少动态效果」设置下的表现。
