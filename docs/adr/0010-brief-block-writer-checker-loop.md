# ADR 0010：简报块改为写作–核查循环（v4-pro 写，qwen3.8 逐句核查，发回同一对话改写）

- 状态：已采纳（2026-10-04），待上线
- 日期：2026-10-04
- 相关：ADR 0004（写作层与检测上限，本文修正了它的两条结论）、ADR 0003（一簇即一块）；用词见 `CONTEXT.md`「写作–核查循环」；
  原型在本地 `apps/backend/prototypes/writer-faithfulness/`（不入库，读数全在其 `out/ref/results.md`，本文是它的入库结论）

## 背景

brief-block-v6 的写作步用 glm-4.7-flash 一次写成。开发集 108–110 期盲评，136 句里确定走样 17 句（12.4%）。
主要是四类：
- 用了被后来报道更新的旧数字；
- 把不同时点的数拼成一句；
- 归属或因果写错；
- 把早期说法当定论。

ADR 0004 的结论"换更大的写作模型只换错法""便宜模型的检测已到上限"，是在 report-v3 输入上测的。
v6 给写作模型的是原句，两条结论在这个输入上都不成立（见下方读数）。

## 决定

1. **写作换 `@cf/deepseek-ai/deepseek-v4-pro-0813`**（关思维链）。提示词、schema、机械校验、补出处都不变。
   标重点（窗口步）仍用 glm-4.7-flash。
2. **写完逐句核查**：每句交给一个 `@cf/qwen/qwen3.8-27b` 小 agent。它用三个检索工具（search / timeline / read）查整簇原文，
   按检查清单（时间、归属、数字、人物身份、关系）逐项核，结论是没问题，或者问题 + 证据原句 + 建议改法。
3. **核查 epoch 可调**，放在 ai-worker 的变量里：默认 1；设 0 就关掉核查，兼作回滚开关。
4. **有问题就改写**：把意见（句号、问题、带发布时间的证据原句；建议改法只作提示）发回写稿的同一个对话，让它整块重写。
   - 改写走同一 schema、同一套机械校验，证据原句也可以引用。
   - 另加一条：改写后句中的数字必须出现在它引的原句里。核查员会自己加数（15+11 写成"26 wounded"），写稿方会照抄。
   - 只复核改过的句子，最多两轮。
5. **出故障照发能发的最好一版，并留痕**：
   - 核查出错 → 发草稿；
   - 改写过不了校验 → 留上一版；
   - 两轮后仍被标记 → 留最后一版。

   不删句、不丢块。每次降级都写进块记录，并汇总到 run 级观测、打 warn 日志。
   不删句是因为核查有误拦：held-out 上没问题的句子被标了 8.5%。
6. **句长上限保持 400 字符**。约束解码会把超长句静默截成半句（"crude colonial mental"），改为触顶即拒收重写。

## 读数

held-out：111–115 期 40 块，丢 1 块（`.'` 句尾被生产校验误拒，各臂一样）。三臂共用同一份草稿配对比较，Opus 盲评、编码时不看臂。

| | 确定走样句 | 按生产篇幅比例 | 改写新引入 | 每块成本 |
|---|---|---|---|---|
| v4-pro 单写（草稿） | 6/152（3.9%） | 3.2% | — | $0.007 |
| 循环，核查 1 次 | 2/152（1.3%） | 1.0% | 1 | +$0.042 |
| 循环，核查 2 次 | 0/152 | 0% | 0 | +$0.083 |

- 年成本按每天 25 块算：写作 +$64；核查 1 次约 +$300，2 次约 +$600。
- 每期估计晚 8–10 分钟。现在一期中位数约 17 分钟。
- 核查员在没见过的句子上（2 次）：确定的错 6/6 全标出；没问题的句子误拦 11/129。误拦只多一次改写，没有改出新错。
- 核查 1 次时新引入的那个错，是核查员自己把数字加了起来（"at least four killed in Kyiv"），所以有了决定 4 的数字检查。

## 证伪清单（别再走）

- **只换写作模型**：glm-5.3-flash 在开发集上的优势到 held-out 没保住（16–17 句，glm-4.7 是 17 句）；v4-pro 单写只降一半。
- **把整个写作步交给一个 ReAct agent**：走样少（2/113），但 6 个头条块里 2 块卡在检索里没写出来，约 $350/年。
  改成小 agent 插进固定流程。
- **逐句改写**（把被标的句子单独拿出来重写）：在同一批句子上修法与整块改写相同，但单句改会和块里其他句子重复。
- **找差异 + 判定拆两步**（为治"看到证据又找理由放过"）：在同等误拦下不比一体的 agent 好。
- **写之前先查数字**：一块 9 个要点花 $0.34，没防住错。
- **核查员换 v4-pro 或混合模型**：准确度与 qwen3.8 持平，每句贵一倍以上；glm-4.7-flash 当 agent 会反复查同一条，用不了。

## 已知风险与后续

- 开发集读数偏乐观：检查清单是照 dev-1 的漏判调的。held-out 每臂只跑 1 次，基线只有 6 个错，核查 1 次与 2 次的差在噪声内。
- 生产并发下的耗时和限流没测（qwen 每分钟 300 次、v4-pro 每分钟 20 次）。上线前先满负荷干跑一期。
- 后续目标：完成时间与成本都降，理想低 90%（基数待定）。候选：
  - 每块一次调用，证据由代码取；
  - 只核高风险句；
  - 写作与改写之间共享前缀缓存。
