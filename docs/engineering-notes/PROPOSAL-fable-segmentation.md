## 0. 结论先行

1. **「③ 按 0.90 切、⑤ 按 0.94 粘」不是标准的 blocking + matching，是两个互相打架的硬阈值分区。**
   两阶段本身必要（LLM 容量上限是实锤），但现在的实例化有三个结构缺陷：③ 的 complete-linkage
   把「候选生成」做成了「不可逆分区」；⑤ 用另一个空间（story centroid）、更严的阈值去撤销 ③ 的
   决定，构造上撤销不了；全流程唯一懂语义的环节（LLM）从来没被问过那个真正要命的问题——
   **「A 组和 B 组是不是一件事」**。调 (0.90, 0.94) 这两个数字的任何组合都到不了「一个事件一条
   story」，因为失败是拓扑性的，不是参数性的。
   *⚠️ R1 补充：切分侧调研进一步确认，「文章两两 cos 阈值一刀切」这个切分判据本身在文献里没有
   对应物（cluster-to-story-segmentation.md §7.1）——所有查到的系统用统计阈值（EventX 共现
   次数/条件概率）或模型选择准则（BIC / Leiden 模块度），没有一个用 pairwise 相似度阈值分区。*

2. **修法的核心是给 ⑤ 换职责：cos 阈值从「决定合并」降级为「提名要问哪些对」，合并由 LLM 两两
   判决 + 非链式聚合决定。** 这是 dedup-band 原型已经验出来的方向（两两问恢复否决能力）。
   *⚠️ R1 订正：这个组合——「已成型的组」当判决单元 + LLM 当判决器——六个角度核实**没有一手文献
   先例**（调研第 5 条）。它的两半各自有先例（pairwise 语义判决 + 聚类聚合是 ER/CDEC 标准骨架；
   「学习型分类器判两个簇要不要合并」Event Registry 用 SVM 做过），拼在一起没有。所以它的性质是
   「设计一个新架构」而不是「抄业界方案」，上线门相应收紧——见 §2「⑤′ 的定位订正」。*

3. **「一个事件占几个名额」分两层解决：事件同一性（occurrence 级）归去重层，简报版面多样性
   （storyline 级）归选择层。** 这是两个不同的等价关系，现在被混在一个 cos 阈值里近似（§6）。
   切分层（③）不背这个锅：它该保持过切偏置，因为切错可由下游合并挽回，粘错则不可逆。
   *⚠️ R5 补充：storyline 关系判定不能用 MMR/DPP 替代 LLM——embedding 核会把同事件碎片判成
   「多样」，这正是要修的失败模式本身，见 §6。*

4. **先建金标再动手。** §5 给出 2-3 人日的标注方案（一次标注、两列标签），指标主用 B-cubed P/R +
   per-event fragmentation，副报 homogeneity/completeness 与 Story Forest 锚定指标名（横向比数值
   无意义，见 §5.2）。**金标建成后有三件近零成本的离线副产品应立刻跑**：阈值-纯度-完整性曲线
   （文献空白，原创数据）、HDBSCAN leaf 臂、③ 现行分区的双指标基线读数。

5. **⚠️ R2：切分判据存在一条我原文漏掉的路——换判据（A′）而非调阈值（A）。** leaf/BIC/Leiden
   都不要求 clique，我的「大事件必碎」论证对它们不成立。但 A′ 撞上另一堵墙：0.90 切分其实身兼
   两职（故事边界假设 + LLM 容量上限），A′ 只接手第一职。结论：A′ 与 ⑤′ 是互补而非替代，
   分两期做，⑤′ 先行——完整论证见 §3.2 与 §3.6。

6. **如果只能做一件事**：重建金标 + ⑤′ 以 mark-only 模式跑两期灰度。理由（已按 R1 重写）在 §8。

## 1. Q1：结构问题在哪

### 1.1 两阶段必要，但现在这个两阶段不是 blocking + matching

ER 文献里的标准三段是 **blocking → matching → clustering**（event-dedup-industry-patterns.md §1）。
职责分工是：blocking 只负责**高召回地生成候选对**（宁多勿漏，错了没有代价，只是多问一次）；
matching 对每一对做昂贵判决；clustering 把两两判决聚合成划分。关键性质：**blocking 的输出是可逆
的（候选对可以被 matching 否决），matching 的判决才是终局的。**

对照现状：

| 环节 | 名义角色 | 实际行为 | 问题 |
|---|---|---|---|
| ③ complete-linkage ≥0.90 | 给 LLM 切容量单元 | 直接产出**分区**，组边界=故事边界的默认值 | ④ 只能在组内拆/剔，**永远不能跨组合并**——切分决定不可逆 |
| ④ story-validation | matching（判「是不是真故事」） | 只见单组，视野被 ③ 锁死 | 唯一懂语义的环节结构性看不到主要失败模式（过碎） |
| ⑤ centroid ≥0.94 全链 | 撤销 ③ 的过切 | 用更严阈值+另一个表示做第二次**几何分区** | 构造上粘不回来（见 1.2） |

也就是说：③ 不是 blocking，是「blocking 兼 clustering 一步做完」；⑤ 不是 matching，是第二个
clustering。真正的 matching（对候选对做语义判决）在文章级从来没发生过，在 story 级只对
两条组发生（storyMerge confirm），≥3 条组无条件合并。

### 1.2 为什么 (0.90, 0.94) 无解：失败是拓扑性的

**③ 端**：complete-linkage 要求组内**所有**对 ≥0.90。一个 91 篇的大事件，早期报道 vs 后期盘点、
现场稿 vs 影响分析，远端配对的 cos 分布必然拖到 0.90 以下——所以大事件在任何「还能保住纯度」的
阈值上都不可能成一个 clique，必碎。实测组中位数 2 篇、最大 16 篇（candidate-grouping.ts 头注），
而尼泊尔洪灾 91 篇 → 22 条 story，正是 clique 直径受 embedding 噪声约束的直接后果。**同机制**
降阈值（路 A）只能把「碎成 22 片」改善成「碎成 10 片」，同时把组做大、撞回 LLM 容量悬崖（§3.1）。
*⚠️ R2 注意适用边界：这段论证只对「clique 型分区 + 降阈值」成立；对不要求 clique 的切分机制
（leaf/BIC/Leiden）不成立，见 §3.2——原文没有把这个边界说清楚，是漏洞。*

**⑤ 端**：把 k 个碎片粘回一片，全链要求 C(k,2) 个 centroid 对**全部** ≥0.94。碎片是 ③ 按
「互相 <0.90」切开的（组间必有低于 0.90 的文章对），其 centroid 对能全过 0.94 的概率随 k 急降。
2026-09-01 改全链后「一场大灾裂成 8 片、占 8 个名额」不是回归，是全链把这个构造性矛盾
**显形**了——单链时代靠 chaining 偶尔能粘回来，但同一机制也在制造中东伞（66% 的多条组内部
有不过线配对）。**单链=错误地粘，全链=正确地不粘，两个都到不了「正确地粘」**，因为「粘不粘」
本来就不该由 cos 阈值终局决定。

**⑤ 还有一刀**：只在同簇内合并（fact 5，cos 0.9497 的跨簇对合不了）。聚类边界在这层被当成
硬约束，于是 ② 的任何切分错误也不可逆。

### 1.3 一句话诊断

> 便宜且语义盲的组件（cos 阈值）在做不可逆的边界决定；昂贵且懂语义的组件（LLM）只被允许在
> 边界内部打杂。修法不是调阈值，是把「边界决定权」移交给 LLM 判决，几何退回提名人的位置。

顺带：③ 的 0.90 只按组内纯度调过、从没按事件完整性评过（fact 2），这不是疏忽，是**当时只有
纯度可测**。所以 §5 的评估方案是一切改动的前置。

*⚠️ R1/R2 补注：切分侧调研第 1 条（所有一手来源的切分动作都是纯几何，LLM 只在切后逐组判定）
**支持而非动摇**本节诊断——它确认「③ 保持几何」是对的；本 proposal 要移交给 LLM 的不是「切分
动作」而是「碎片是否同一事件的合并判决」，这在文献里是另一个位置（见 §2 定位订正）。同时调研
确认了「切多深」的业界答案是统计阈值或模型选择准则、从不是 pairwise 阈值一刀切——即 ③ 现行
判据连「业界标准的几何切分」都不算，这是 §3.2 A′ 的出发点。*

### ⑤′ 的定位订正（⚠️ R1，2026-09-02 新增——正面处理「无先例」问题）

**原判断「⑤′ 在 ER 框架里是标准 matching」部分作废。** 精确的说法分三层：

1. **成立的部分**：「pairwise 语义判决 + 聚类聚合」是 ER 六十年的标准骨架，且 CDEC——恰好就是
   新闻事件领域——的标准流程逐字就是这个（event-dedup-industry-patterns.md §3.2："pairwise
   mention scorer + agglomerative clustering"）。「判决器判两个**簇**要不要合并」也有生产先例：
   Event Registry 用 SVM 做跨语言簇合并判定（85 样本、10 折交叉 87% 准确率，exhaustive note
   §2.1）；EventX 第二层用 SVM 判文档对。**「组对 + 学习型判决器」这个位置存在。**
2. **不成立的部分**：判决单元是「已成型的 story 碎片」+ 判决器是 zero-shot LLM——这个具体组合，
   切分侧调研六个角度核实**无一手先例**（cluster-to-story-segmentation.md ⓪-5/§4.1）。
   坐在那个位置上的从来是训练出来的分类器，不是 prompt LLM。
3. **所以第 5 条负面发现的杀伤力是**：它不能否定架构位置（位置有先例），但剥夺了「业界标准做法」
   这块挡箭牌——⑤′ 是**新组合**，没有前人的失败记录可查，坑要自己踩。

**「空白=机会」还是「空白=前人试过没成」？** 两个论据支持前者，均为推断、如实标注：

- **成本结构论**（推断）：这个位置需要一个免训练的语义判决器。LLM 之前它不存在——SVM 要标注
  训练集（Event Registry 也只在跨语言这一处用，85 个样本），所以文献在这个位置的沉默与
  「试过失败」的沉默**不可区分**；但 zero-shot LLM 把建判决器的边际成本打到接近零，成本结构
  变了，空白值得重探。这是解释不是证据。
- **本域直接证据**（实测）：dedup-band 原型在我们自己的数据上验了最险的一环——两两判决恢复
  判官否决能力（Modi 中亚行 / 委内瑞拉两组人裁全对，3 个关键否决对被整组问淹没、两两问救回）。
  **对「这套数据+这个 prompt+这个任务」的直接实测，比「文献里有先例但换个域」更硬**。文献先例
  的作用本来就是替代不了本域 eval 的，我们恰好已经有了本域原型证据、缺的是文献背书——比反过来
  （有背书没证据）处境好。

**无先例的后果落实为三条硬约束**（从「风险缓解」升格为上线门）：

- 金标（§5）建成前不碰生产路径（原有）；
- **⑤′ 判决先以 mark-only 模式随生产跑满两期**：判决落库、不改简报，与现行 ⑤ 输出差分人审
  后才允许切换——无先例意味着未知失败模式只能靠灰度扛，这一步不可跳过；
- kill criteria 预注册：金标上判官 pairwise precision <0.90 → 先收紧候选带重测一轮，仍不过
  → ⑤′ 降级放弃，回退到「A′ + 配额」的保守组合（§3.6）。

**这不改变「只做一件事选 ⑤′」的结论**，理由见 §8；但把 §8 的表述从「原型已验通」修正为
「原型验通了核心机制，整体组合仍需灰度自证」。

### ⑤′ 事件归并——机制设计

**(a) 提名（几何，零 LLM）**
- 同簇：story centroid 余弦 **≥0.90**（现 0.94 → 0.90，dedup-band 实测配对 11 → 93/期）。
- 跨簇：story centroid 余弦 **≥0.93**（比同簇严，先用 SQL 探针量清楚每期会提名几对再定；
  现有那个 0.9497 的实例会被覆盖）。
- 输出：候选边集合，按连通分量分块。分量大小实测 ≤12（尼泊尔 12 条），最大问询量 C(12,2)=66 对。

  *跨簇提名与「去重层不越权」的关系*：memory `clustering-prune-overreach` 的教训是**几何静默
  越权**（质心剪枝 0.92 直接删文章）。这里几何只提名、LLM 判决、判决落库可审计——越权的三要素
  （静默、无判决、不可逆）一个都不占。但要设跨簇合并的观测计数，若某期跨簇合并 >5 次，说明
  ② 在系统性切错，该去修聚类而不是靠这层兜。

**(a′) 树引导提名（⚠️ R3 新增，二期）**
- cos 带提名有一个已知召回缺口：同一大事件的远端碎片（如「灾情主线」vs「铁路项目影响分析」）
  centroid 对可能 <0.90，永远不被问。二期用切分侧调研给出的结构补上：对超大簇离线跑
  HDBSCAN leaf（或 BIC 递归二分），得到「事件假设树」；**同一 leaf/BIC 父节点下出来的碎片
  互相自动获得提名资格**，不论 centroid 是否过带。树只提名、不合并，合并仍由 (b)(c) 决定
  ——与 (a) 的分工完全一致，只是提名信号从「centroid 近」扩展为「密度树同源」。
- 这一步先在金标快照上离线量「带内提名 vs 树引导提名」各自的召回（漏了哪些金标同事件碎片对），
  证明缺口真实存在再上——若 0.90 带的提名召回已 ≥95%，(a′) 不做。

**(b) 判决（LLM，逐对）**
- 每条候选边一次 `getStoryMergeConfirmPrompt`（现成 prompt，判准不动），输出
  same_occurrence: true/false。**不再有「≥3 条组免确认」**——那条豁免的依据已被 dedup-band
  证伪（整组一问=橡皮图章，3/3 全同意含「关税×湖改名」）。
- 判决缓存：以 (storyA 文章集 hash, storyB 文章集 hash) 为 key 幂等落库，workflow 重放不重问。
- 并发 8-10（Workers AI 300 rpm 上限内），93 对约 1-2 分钟墙钟。成本：glm-4.7-flash
  ~38 neurons/次 × 150 ≈ 6k neurons/期，约 $0.03-0.05/期，可忽略。

**(c) 聚合（确定性，零 LLM）——用 LLM 判决当边，选非链式算法**

这里是唯一真正开放的算法问题，**不拍板，设四臂在金标上对照**（⚠️ R1 补第 4 臂 c0，来自切分侧
调研 §7.3 的替代建议，纳入对照以证实/证伪）：

| 臂 | 算法 | 性质 | 预期失败模式 |
|---|---|---|---|
| c0 | 逐组打事件标签，标签相同（embedding/字符串匹配）自动合并 | 最便宜，O(组) 次调用 | 标签粒度不可控（「尼泊尔洪灾」vs「尼泊尔冰湖溃决」匹配不上=阈值问题换个位置重现；伞标签把整簇粘回=过合无否决）。预判为弱臂，纳入是为了用数据否掉而不是拍脑袋否掉 |
| c1 | complete-linkage over LLM-yes 边 | 最保守 | 判官单个 FN 边就拦下整组（尼泊尔 65/66 同意仍拆成 11+1，人裁为轻微误拆）——对判官噪声零容忍，大事件仍会残碎 |
| c2 | **star/CENTER**：按 LLM-yes 度数最高者当中心，与中心直连的并入；剩余节点重复 | Hassanzadeh et al. 2009 实测精度+效率双高的那档；深度 1，构造上无 chaining | 中心选错时划分错（dedup-band 已见：贪心 clique 抢走「Canada 立牌」）；并列度数需确定性 tie-break（取 index 最小） |
| c3 | quorum：分量内 yes 率 ≥2/3 整体合并，否则退 c2 | 对判官噪声最鲁棒 | 分量里混进一个真不同事件时会被多数票裹挟（Milo 型假阳被放大） |

判据：金标上的 B-cubed P/R + per-event fragmentation（§5），c2 为默认候选。
**明确不用**：单链（chaining 已证）、correlation clustering 近似解（文献实测不赢启发式，
industry-patterns §2.2/§7.3——别为理论优雅买单）。

**(d) 合并执行**：现成 `collapseGroup`（importance 取 max、30 篇时间均匀取样、起新标题）全部沿用。

**已知风险（不粉饰）**：
- **判官假阳**（Milo：遣返阿富汗人 × Milo 被遣返，两两问也没救回来）。0.90 带比 0.94 带装进更多
  「同题材不同发生」，假阳暴露面变大。缓解：(i) 判准里 full coreference 与 subevent/follow-up
  分开问（Araki et al. LREC'14——注意切分侧调研 §5 确认：三分类是学术共识，但**没有一手来源给出
  可操作的判定规则**，prompt 怎么拆要自己设计+在金标上测，没有现成公式可抄）；(ii) 金标上量
  pairwise precision，kill criteria 见定位订正。
- **无先例风险**（R1）：未知失败模式无前人记录，只能靠 mark-only 灰度 + 预注册 kill criteria 扛。
- **BF16 非确定性**：temperature 0 也不保证同问同答（exhaustive note §1.1）。判决落库缓存
  顺带解决重放一致性，但两期之间同一对可能翻面——接受，因为每期输入本来就变。
- **墙钟**：去重 step 现在是串行 11 次调用，改 93-160 对必须先并发化（dedup-band 提议 #4），
  且该 step 要留在 25 分钟预算内（memory：step 墙钟刚提到 25 分钟）。

### ⑥′ 选择层：storyline 配额（详见 §6，这里只列机制）

- 排序不动（score = importance + log2(1+srcs)）。
- 取排序后 top-40 候选，**一次** LLM 调用：40 个标题分 storyline（「哪些标题属于同一条新闻
  线索」）。40 条短标题在容量安全区内（退化从 ~20-100 条开始，且这里判错的爆炸半径只是
  配额记错，不丢文章）。
- 确定性配额：top-25 内每 storyline 最多 K=2，超出的顺位替换为下一个不同 storyline 的候选
  （已实测 K=2 时 distinct 事件 17.6 → 19.0）。
- **配额触发次数是传感器**：⑤′ 工作正常时配额应很少触发；某期触发 >3 次 = 上游归并失效的
  报警，别把配额当治疗。
- *⚠️ R5：为什么这次 LLM 调用不能省成 MMR/DPP——见 §6，机制性理由。*

### 调用量与成本合计

新增 ~110-170 次小调用/期（全部 glm-4.7-flash 级），+$0.05/期以内，墙钟 +2-4 分钟（并发 8-10）。
对比基线：④ 现状 ~150-250 次/期不变。

## 3. Q3：评价 A / A′ / B / C / 配额

### 3.1 A（同机制降 0.90 → 0.85/0.80）：作为「修法」是伪解，作为「测量」可以蹭——判定不变

- 反对理由 1：complete-linkage 组大小随阈值降而涨，0.80 时组会进入 30-50 篇区间——正是
  multi-instance 退化区（ρ=−0.61 那条受控实验），④ 的 89-92% 精度是在中位数 2 篇、最大 16 篇

- 反对理由 2：§1.2 已论证大事件在任何合理阈值上都不成 clique，A 治标不治本，还把 ③ 唯一的
  优点（组小、LLM 舒适区）交出去了。
- 保留价值：**建完金标后**顺手跑一条 0.85/0.88/0.90 的纯度-完整性曲线（零 LLM、纯离线）。
  ⚠️ R4：这条曲线的地位上调了——它不只是诊断图，还是文献空白处的原创数据（§5.3）。
  但**作为修法**的判定不变：最低优先级。
- *⚠️ 与切分侧调研的关系澄清：调研 §7.2 的首选不是 A，是换判据——那是 A′，另一个提议，
  两者不矛盾。我原文的错误是只驳了 A、没意识到 A′ 这条路存在。*

### 3.2 A′（换切分判据：leaf / BIC / Leiden）——⚠️ R2 新增，原文漏项，逐个过「必碎」论证

我的拓扑论证依赖一个前提：**分区机制要求组内两两全过线（clique 型）**。逐个检查：

| 机制 | 「必碎」论证是否适用 | 理由 |
|---|---|---|
| HDBSCAN leaf（对超大簇重跑或解析 condensed tree） | **不适用** | 密度树叶子沿密度谷切，组大小不受两两最小相似度约束；一个密度连续的大事件可以整体留在一个 leaf 里 |
| BIC 递归二分（Event Registry 式） | **不适用** | 模型选择准则：拆开后拟合优度提升不抵复杂度代价就不拆——判据方向恰好是「连贯的大事件不该拆」；且是文献里唯一查到的自适应 split 判据一手先例 |
| Leiden 模块度递归（GraphRAG 式） | **不适用** | 模块度不要求全连通，密集子图整体成社区，深度自动终止 |

**所以「换判据能绕过拓扑障碍」成立，原文对切分侧的悲观是过度概括。** 但 A′ 有两个自己的问题，
决定了它不能单独成为修法：

1. **撞 ④ 的容量墙**。现行 0.90 切分身兼两职：故事边界假设 + **LLM 容量上限的保证**（组最大
   16 篇）。A′ 正确地把 91 篇大事件保成一个组的那一刻，④ 就没法验它了——判官精度 89-92% 是在
   小组上测的，塞 91 篇回到「整簇喂 LLM、36% 静默漏掉」的死地。要接住这个组，要么 ④ 改成
   采样验证（时间均匀取 15-20 篇判「是不是一个连贯事件」——**新的未验证设计**，样本可能掩盖
   伞状混装，伞恰恰是 verify 环节的头号敌人），要么保留 ③ 做纯容量切分、A′ 的树只当 ⑤′ 的
   提名向导（= §2 的 (a′)）。**我推荐后者**：它不新增任何未验证的 LLM 任务形态。
2. **leaf 保不保得住大事件是未知数**。大事件的不同侧面（学校撤离 vs 水电站救援 vs 外交争议）
   词汇差异可能在密度上造谷，leaf 照样切开——只是切在自然边界而非任意 clique 边界。碎片数
   预期少于 22，但不保证是 1。**这正好是金标能零 LLM 离线量的**：对快照里的大簇跑 leaf 臂，
   直接读金标事件的 fragmentation φ。BIC 同理。

**优先级**：离线评估**提前**（金标建成即跑，零 LLM、几小时量级）；生产落地放二期，角色是
⑤′ 的提名升级（(a′)）与 ③ 判据的候选替换，且要与 ⑤′ 分期上线以便归因（§3.6）。

### 3.3 B（小簇整簇喂 LLM，跳过切分）：无害的效率优化，不解决主诉——判定不变

- 支持面：≤12 篇的簇确实在容量安全区，④ 的 judge prompt 本来就支持一组出多个事件。
- 反对面：主诉（fact 2）全部发生在**大簇单一事件**上——B 恰好只覆盖不出问题的那部分。

- **优先级：中低。⑤′ 落地后做。**

### 3.4 C（把「这组和隔壁组是不是一件事」加进 ④）：方向对，落点错，应落成 ⑤′——判定不变

1. **归因**：两个都动，φ 降了不知道该谢谁，φ 没降不知道该怪谁。金标快照上可以并行评（零干扰），

2. **风险结构**：⑤′ 是「合并能力」——它存在之后，上游任何切分机制的错误都变成可挽回的，

## 4. Q4：「一个事件占几个名额」该在哪层解决

三个判据：

| 判据 | 切分层 ③ | 去重层 ⑤ | 选择层 ⑥ |
|---|---|---|---|
| **信息可得性**：判断「同一事件」需要把双方语义并排看 | 只有文章两两 cos，无事件概念 | **唯一**同时持有双方标题+成员+centroid 的层 | 只有标题和分数 |
| **错误可逆性** | 过切可由 ⑤ 挽回；过合出伞状组、④ 会橡皮图章，**不可逆** | 误合→报告写混两件事，下游无拆分机制，**不可逆**；误不合→⑥ 还有配额兜 | 误压 story 损失一个名额，**当期可审计、次日可调 K**，最可逆 |
| **修复的收益面** | 只影响 LLM 调用形状 | **名额 + 报告质量双收**（合并后报告吃全谱材料） | 只收名额 |

结论：
- **事件同一性（合并）归 ⑤**：它是唯一有信息做这个判断的层，且只有它能同时救回名额和报告质量。
- **版面多样性（配额）归 ⑥**：作为 ⑤ 误不合的最后防线 + 独立的编辑策略（两个真不同的大事件
  同 storyline 时也该限额），错误代价最小。
- **③ 不参与**：给它加「少切」的责任 = 让它冒过合的险，而过合在本管线里恰好是最不可逆的错误
  （④ 对既成组恒答是）。③ 的正确姿势就是**保持过切偏置**——切碎无罪，前提是 ⑤ 有粘回的能力。
  现在的病根正是 ⑤ 没有这个能力，而不是 ③ 切太碎。

*⚠️ R2 补注：A′（§3.2）不与本节矛盾。A′ 改善的是 ③ 「切在哪」的判据质量（沿密度谷切而非沿
clique 边界切），不是给 ③ 加「少切」的语义责任——事件同一性的终局判决仍在 ⑤′。切分侧调研
第 1 条（切分动作全是几何）与本节分工完全一致。*

## 5. Q5：评估方案（成本可控）

### 5.1 标什么

**一次标注，两列标签**（这是省钱的关键，也直接服务 §6 的双关系设计）：

1. **文章级事件划分金标**（喂 ③/⑤′ 的 B-cubed）
   - 取 2-3 期快照（dedup-band 原型已能连 Neon 取真数据），分层采样 12-15 个簇：
     每期 1-2 个大单事件簇（尼泊尔型，>40 篇）、1-2 个伞状簇（多事件混装）、4-6 个中小簇。
     合计 ~300-400 篇。
   - 人读标题+摘要，把每簇文章划分成事件（含「不属于任何事件」桶）。~15-20 秒/篇，
     **2-3 小时/期，总计 1-2 人日**。
2. **story 对金标**（喂 ⑤′ 的 pairwise 判官与聚合臂）
   - 对同批期次，取 centroid cos ≥0.88 的全部 story 对（放宽到 0.88 是为了让同一份金标能评
     0.90/0.92/0.94 任何候选带），每对标两列：
     `same_occurrence`（同一发生？——⑤′ 判官的尺）和 `same_storyline`（同一条新闻线索？
     ——⑥′ 分组的尺；SCO 峰会 × 乌兹别克国事访问 = occurrence 不同、storyline 相同，正是
     那对「判官判对了但简报仍重复」的病例）。
   - 估计 ~100-200 对/批，读标题即可，半天。**这就是丢失的 94 条金标的重建+扩容。**

标注卫生：单人主标，随机 20% 双标测一致性；预期 κ 0.6-0.75（文档内显著性任务人际 κ 0.56 的
先例摆着，别拿 κ>0.8 当验收门）；分歧写进 rubric 裁定政策（照 intel-grounding 的「人裁终裁」
模式）；金标落 git（教训：上一批就是没落 git 丢的）。

### 5.2 用什么指标同时量纯度和完整性（⚠️ R4 修订：补两套指标的关系论证）

对（系统划分 vs 金标划分）：

- **B-cubed precision** = 组内纯度（每篇文章所在系统组里同事件成员占比，按文章平均）
- **B-cubed recall** = 事件完整性（每篇文章的同事件伙伴被收进同一系统组的占比）
- **per-event fragmentation** φ(e) = 覆盖金标事件 e 的系统 story 数，按事件 macro 平均
  （直接量「一个事件几条 story」；必须 macro——pair 级指标会被大事件二次加权，
  memory `clustering-recall-first-metrics` 的坑）
- **产品级终指标**：top-25 中 distinct 金标事件数（简报真正买到的东西）

**与 Story Forest 的 homogeneity / completeness / V-measure 是什么关系**（切分侧调研 §3.1
提出的锚）：同一对权衡的两套形式化——homogeneity/completeness 基于条件熵（簇内类别混杂度 /
类别跨簇散落度），B-cubed 基于逐条目重叠占比。互补，不等价。**主指标选 B-cubed + φ**，理由：

1. `scripts/eval/clustering/` 已有 B-cubed 工具，B-cubed 也是 CDEC 领域标准（调研 §3.2）；
2. per-article/per-event 的量能下钻——φ 直接读出「尼泊尔碎成几片」，条件熵读不出具体是谁碎了；
3. 形式性质上 B-cubed 满足 rag-bag 等约束（Amigó et al. 2009 的形式约束分析；**此条出自
   本文作者文献记忆，未在本仓库调研笔记中核实过，采信前可查原文**），我们有噪声桶，正好相关。

**homogeneity/completeness 作为副读数一并打印**（实现 ~10 行）：想对齐 Story Forest 指标名的
读者有得看。但**横向比数值无意义**：V-measure 的熵归一化对类数与类分布敏感，Story Forest 是
60GB 中文语料 3,500 篇标注集，与我们的数据分布毫无可比性——0.960 不是我们的目标线，
**别把它写进验收判据**。

### 5.3 阈值-纯度-完整性权衡曲线：升为独立产出（⚠️ R4 新增）

切分侧调研 §3.3 确认：「阈值调高→纯度上去→碎片化」的量化权衡曲线**在新闻事件领域没有任何
论文报告过**（Story Forest 只报单操作点，Matryoshka 没做同层扫描，最接近的一篇在对话分割域
且只给了方法论）。金标建成后，对 ③ 的阈值扫 {0.80, 0.85, 0.88, 0.90, 0.92}，同时对 leaf/BIC
臂各取一点，报 B³-P/R + φ + homogeneity/completeness 双套读数——**零 LLM、离线、约一天**。

定位说清楚：它同时是 (i) A 的诊断图（§3.1）、(ii) A′ 臂的评估载体（§3.2）、(iii) 文献空白处的
原创数据，可沉淀为一份工程笔记。**但它是产出不是目标**——别让画曲线推迟 ⑤′ 的灰度。

### 5.4 怎么跑

冻结 2-3 期输入快照（embedding + 文章 + 簇），旧管线 vs 新管线**离线**重放（dedup-band 原型
就是这个形态，⑤′ 四臂 + A′ 臂在同一快照上跑），对拍上述指标。LLM 判决逐对落盘
（eval-probe hygiene 六断言 + 并发 worker pool 照 `_shared/hygiene.ts` / expand.ts 的既有模式）。

### 5.5 验收判据（先写死，防事后找补）

- 最大金标事件的 φ：基线 8-22 → **≤2**
- B-cubed precision 相对基线跌幅 **≤2pp**（合并不能以引入伞为代价）
- top-25 distinct 金标事件数 **+≥3**
- ⑤′ 判官 pairwise precision（对 same_occurrence 金标）**≥0.90**，达不到就收紧候选带重测，
  仍达不到则 ⑤′ 不上生产（kill criteria，见 §2 定位订正）

### 5.6 无金标期的常驻传感器（零标注成本）

每期简报产出后，对 top-25 内 cos ≥0.85 的 story 对（约几十对）跑一遍 pairwise 判官，
记录「same_occurrence 或 same_storyline 判真」的对数，mark-only 落 R2。这是去重层的
线上回归表，模式照 B1 纯传感器（memory `intel-grounding-judge-validated`）。

## 6. Q6：没想到的角度——你们在用一个等价关系近似两个

管线里所有层都在逼近「同一事件」，但产品目标「一个名额一块」实际由**两个粒度不同的等价关系**
支配：

1. **occurrence coreference**（同一个具体发生）——⑤ 的 CRITERIA 写的就是它，rescue/死亡数
   更新/后续谈判都算同一 occurrence。这是**合并**的正确判准：合错了报告会写混。
2. **storyline membership**（同一条新闻线索的不同发生）——SCO 峰会和乌兹别克国事访问是
   两个 occurrence，但都是「Modi 中亚行」这条线；FINDINGS 末尾那条「订正」说这对重复
   「去重层不该管」——**对，但也没有任何一层在管**，于是它以简报内容重叠的形式漏到读者面前。
   这是**名额**的正确判准：同 storyline 的两块在版面上就是重复感，哪怕事实上是两件事。

CDEC 文献里这两者是被分开建模的（full coreference vs subevent/membership，Araki et al.
LREC'14）。现状是用 cos 阈值一个旋钮同时近似两个关系：拧松了 occurrence 层出伞，拧紧了
storyline 层漏重复，**无解不是因为阈值没调好，是因为一个标量装不下两个关系**。

*⚠️ R1 注：切分侧调研 §5 对 Araki 三分类的核实结果要如实转达——三分类是共识，但**没有一手来源
给出可操作的判定规则/特征清单**（LREC PDF 两次抓取失败，只到摘要级）。所以「把判准拆开问」是
有背书的设计方向、没有可抄的公式，具体 prompt 拆法要在 §5 金标上自测。*

拆开之后各归其位（§2 已落）：occurrence 判准给 ⑤′（合并），storyline 判准给 ⑥′（配额）。
而 ⑥′ 之所以能用 LLM 做「分组」这个在文章级被判死刑的动作，是因为**规模坍缩了**：
1000 篇文章 → 排序后 40 个短标题，正好落回 LLM 的容量安全区。判错的爆炸半径也小：最坏是某
story 被误配额，损失一个名额，不丢任何文章、不污染任何报告。

### storyline 分组能不能用 MMR/DPP 替代那次 LLM 调用？（⚠️ R5 新增：不能，机制性理由）

诱惑很实在：DPP/MMR 零 LLM、确定性、有工业 A/B 先例（Chen et al. NeurIPS 2018），还有 2025 年
新闻多文档摘要的直接应用（调研 §6.3）。但**在我们的场景里它替代不了 storyline 判定**，
理由是机制性的，切分侧调研 §6.5 自己已经给出一半：

1. **MMR/DPP 的多样性度量就是 embedding 距离，而 embedding 距离在这个问题上是已被实测证伪的
   信号**。同一大事件的碎片恰恰因为 embedding 互远才碎的（学校撤离 vs 水电站救援 vs 外交争议）
   ——DPP 的核矩阵会把这 22 片判成「非常多样」，兴高采烈地把配额发给它们。**用 DPP 做配额 =
   把观测到的失败机制直接写进选择器**。
2. 仓库自己的实测：cos 在 0.94 邻域连 occurrence 都分不开（「基辅袭击 vs 泽连斯基无人机计划」
   0.9445 不该合，夹在两个该合的 0.9579/0.9423 中间）——更抽象的 storyline 关系（cos 可能低到
   0.7x）更不可能由几何判出。**storyline 是语义关系，必须语义判决器**。
3. **正确分工**：关系判定（谁和谁同线索）→ LLM；关系已知后的选择机制 → 确定性配额就够了。
   n=25 名额、storyline 标签在手的情况下，「每 storyline ≤K」比 DPP 的 MAP 推断更可审计、
   可调、可解释；DPP 在这个规模上没有增量收益，只有解释成本。**若将来 ⑤′+⑥′ 都工作正常、
   还想在 25 块之间做题材层面的软多样性（政治/经济/灾难配比），那才是 DPP/MMR 的合法位置。**

fallback（storyline 分组的 40 题调用若在金标上误配率高）：退到「top-40 内 cos ≥0.75 的对
逐对问 same_storyline」（~40-80 次小调用），用已验证的 pairwise 形态换掉未验证的分组形态。

**次要的漏配角度（记录在案，不展开）**：事件身份不跨天。尼泊尔洪灾连烧几天，每天管线从零
重新推导事件，昨天占过名额的事件今天原样再占。流式质心匹配 / story registry（Miranda
EMNLP'18、Story Forest）是成熟先例，但那是架构改造，超出 ②→⑥ 当期范围；⑤′ 落库的
事件 centroid + 判决缓存恰好是将来做跨天身份的现成地基——设计 ⑤′ 的存储时留这个心眼
（事件行带稳定 id 和 centroid，别只存当期临时结构）。

## 7. 各提议的失败模式一览（集中重申，防选择性阅读）

| 提议 | 失败模式 | 探测方式 |
|---|---|---|
| ⑤′ 整体（无先例组合，R1） | 未知失败模式，无前人记录可查 | mark-only 两期灰度为上线门；kill criteria 预注册（判官 precision <0.90 降级/放弃） |
| ⑤′ 候选带 0.90 | 判官假阳被放大 → 伞状合并回潮 | 金标 pairwise precision <0.90 即停；线上传感器 §5.6 |
| ⑤′ star 聚合 | 中心选错 → 划分错（关税/立牌/湖改名型） | 四臂对照的 φ 与 B³-P 分歧处人工复核 |
| ⑤′ c0 标签臂 | 标签粒度不可控：同事件异名合不上，伞标签全粘回 | 金标对拍，预判为弱臂 |
| ⑤′ 跨簇合并 | 变相替聚类层擦屁股，掩盖 ② 的系统性错误 | 跨簇合并计数 >5/期报警 |
| A′ leaf/BIC 臂（R2） | 大单事件仍沿密度谷碎（φ>1 无保证）；正确保整的大组撞 ④ 容量墙 | 离线金标直接量 φ；生产上只当提名向导 (a′)，不让大组直达 ④ |
| ⑥′ storyline 分组 | 40 条仍可能漏配/幻觉 id | 白名单校验 id；配额触发日志人工抽查；fallback 见 §6 |
| 配额代理版（clusterId） | 一簇多真事件被误压 | 被压 story 落日志，抽查误压率 |
| B（小簇整簇喂） | 判官从零分组的退化未验过 | 先 10 簇对照（整簇 vs 先切）再放量 |
| A（同机制降阈值） | 组变大撞容量悬崖，④ 精度失效 | 只进 §5.3 曲线，不上生产 |
| 金标 | 人际一致性天花板不高，单人偏置 | 20% 双标 + 裁定政策入 rubric |

## 8. 如果只能做一件事（⚠️ R6 重写）

**重建金标（§5.1，1-2 人日），然后把 ⑤ 改成「0.90 带提名、LLM 逐对判决、star 聚合」（⑤′），
以 mark-only 模式随生产跑满两期再切换。**

这个选择在读完切分侧调研后**维持不变**，但理由的构成变了，如实交代：

- **原理由「原型已验通」降级为「原型验通了核心机制」**：无先例（调研第 5 条）意味着整体组合
  的未知失败模式没有前人记录，所以 mark-only 灰度从可选项变成上线门，交付周期比原版长两期。
- **维持选它的三条理由**：
  1. **它是唯一交付「合并能力」的选项。** 有先例的替代路（A′：leaf/BIC/Leiden）交付的是
     「少切」，不是「能粘」——leaf 对大事件保整无保证（φ 可能仍 >1），跨簇碎片它根本看不见，
     而正确保整的大组反而撞 ④ 容量墙。无论切分侧怎么升级，残余碎片总要有一层能粘回去；
     这层只能是 ⑤′。**先例的有无改变的是上线的谨慎程度，改变不了依赖结构。**
  2. **证据强度排序**：⑤′ 核心机制有本域原型实测（两两判决恢复否决、人裁 4/7 组正确），
     A′ 在我们数据上的行为完全未测。「本域直接证据、缺文献背书」好过「有文献背书、零本域
     证据」——文献先例本来就替代不了本域 eval。
  3. **风险结构**：⑤′ 存在之后，上游一切切分实验（A′、B、阈值曲线的任何结论）都变成可挽回的
     低风险改动；反序则每一步都在无兜底状态下动刀。
- **顺手带走的免费项**：金标建成当天，零 LLM 离线包（§5.3 曲线 + A′ 臂 + 基线双指标读数）
  一并跑掉——它们决定二期（(a′) 树引导提名 / 换 ③ 判据）做不做，且不占 ⑤′ 的关键路径。
- **止损线**：若 ⑤′ 判官在金标上 precision <0.90 且收带重测仍不过，⑤′ 放弃，回退组合为
  「A′（换切分判据，少切）+ 配额（止血）」——那条路合并能力缺位，接受 φ 落在 2-5 区间、
  靠配额控名额，是明确写下的次优解，不是隐性期望。
