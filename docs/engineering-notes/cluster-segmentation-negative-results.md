## 〇、一句话

**「把一个簇切成事件」这件事，LLM 和几何都做不稳；而事件内部那条边界（救援 vs 伤亡 vs 成因）
根本不存在客观答案。真正能修的是上游聚类质量，而它现在缺的是特征不是算法。**

## 一、已证伪（别重试）

### 1.1 让 LLM 一次性划分整簇 ❌

**做法**：把一个簇的 60–147 条标题喂给 glm-4.7-flash，让它输出完整划分。生产现行做法。

**读数**：同一 prompt、同一输入、`temperature=0`、`skipCache=true`，簇 49（57 篇）跑 6 次得到
**48 / 48 / 53 / 10 / 45 / 13**——5.3 倍差异，且在两个**相反**的病之间跳：

- 几乎不合并：57 篇出 53 条，`8/29: CBS Weekend News` 都单独成一条
- 合过头：塌成 `Sudan conflict` / `Syria's political and social developments` / `Opinion and analysis`

**六种 prompt 写法零可复现改善**（BASE / DROP / SYMDEF / NAMETEST / NEST / STACK）。其中：

- 在保留「一个 occurrence 可以有多条主线」授权的前提下**加反向禁令** → glm 进复读死循环，
  `finish_reason=length`、completion_tokens 打满 4000、同一条主线重复几十遍 → JSON 截断 → 解析 0 条
- **整个改写任务定义**成「列出这里有哪些 happening」 → 60 条标题进、60 条出，名字大量重复，
  退化成逐条抄标题
- **多条约束叠加**（STACK）比单用最好那条更差
- 唯一一次看似成功（SYMDEF 把洪灾收成 1 条）**三轮后未复现**：同配置重跑得到 5 / 11 / 8

**机制**：这是已知的容量失效，不是 prompt 问题。受控实验（见 `exhaustive-assignment-and-singleton-events.md`）
显示条目数 n 在 20–100 开始退化、n≥200 崩塌；而把每条**加长一倍**（token 翻倍、条目数不变）几乎不掉。
Pairwise Ranking Prompting 论文记录的 listwise 四种失败模式里，**Inconsistency**（同批候选换个顺序
输出排列就不同）与此同构。

**推论**：**加信息也没用**。实测给每条标题挂上 `key_entities` + `primary_location`，输入 tok
1574 → 5561，截断从 8 次涨到 10 次、整轮 FAIL 从 1 轮涨到 2 轮。加的是 token 不是减条目数。

**去掉输入截断也不行**：`PLAN_TITLE_CAP=60` 当初是为压**输出**加的，不是输入塞不下（147 条标题
约 4k tokens）。去掉后 12 次尝试 8 次输出打满被腰斩。**输入 cap 与输出上限是绑死的。**

### 1.2 HDBSCAN 换 `cluster_selection_method='leaf'` ❌ 零效果

**假设**：EOM 会「选父簇并取消选中其全部后代」，所以子结构被算出来又扔了，换 leaf 能捞回来。

**读数**：全量 1031 篇上 eom 与 leaf **逐点标签完全相同**（`(eom==leaf).all() == True`）。
直接读 `condensed_tree_._raw_tree`：生产簇 55 落进的两个 eom 簇内部**被取消选中的后代节点数 = 0**。

**机制**：`cluster_selection_epsilon=0.35` 把 condensed tree 在该距离以下**压平了**，树里根本没有
子结构给 leaf 选。对照：同一份 UMAP 输出、`epsilon=0` 时子结构存在（eom 149 簇 / leaf 162 簇），
但那 147 篇随即碎成 22–24 组、34–41 篇掉进噪声。

**边界**：`eom` 与 `leaf` 在 `eps ≥ 0.30` 时输出逐字相同（三个种子全对上）。**method 这个参数只在
`eps ≤ 0.20` 才是活的。**

### 1.3 换 Leiden 图聚类 ❌ 没有稳定性优势

NewsCatcher 官方文档说他们把聚类从密度聚类换成 Leiden 就是为了稳定性。实测不复现：

```
                              跨种子 ARI（F1 / F2）
HDBSCAN eps=0.35（生产）        0.861 / 0.737     ← 全扫描里最稳
Leiden 最好那个配置              0.958 / 0.387     ← 换个窗口就崩
```

另外粒度也对不上：12 个配置在 1031 篇上只出 5–25 个社区（生产 50 个簇），`resolution` 只扫到 1.5，
**没覆盖到生产粒度**。Leiden 没有噪声概念，1031 篇全部进社区，杂讯只会埋得更深。

### 1.4 用几何切事件内部边界 ❌

四臂对照（LINKAGE 全链 cos≥0.90 / LEAF / BISECT k-means+BIC / Louvain），簇 55（洪灾 102 篇）：

| 臂 | 洪灾收在一起 | 混入杂讯 | 洪灾碎成几组 | 单篇组 |
|---|---|---|---|---|
| **BISECT 只切第一刀** | **102/102** | 7 | **1** | **0** |
| BISECT 递归到底 | 43/102 | 3 | 3 | 0 |
| LEAF（生产参数） | 102/102 | 12 | 1 | 1 |
| Louvain | 12/102 | 1 | 13 | 0 |
| LINKAGE cos≥0.90 | 18/102 | 0 | 28 | 50 |
| LINKAGE cos≥0.94 | 10/102 | 0 | 68 | 95 |

**只要有任何「继续往下切」的判据介入，同一场洪灾必碎。** BISECT 跑到底会切成 46/36/24 三块——
救援 / 死亡数字滚动 / 堰塞湖与中方，正是三个角度而非三件事。

**而且大部分簇上「那一刀」不是良定义的对象**：11/13 的簇里 k-means 有近似简并的多个最优解，
inertia 只差 0.3%（如簇 21 五次 10.183–10.215）但划分天差地别（簇 20 两个种子 ARI 仅 **0.04**，
49 篇里 33 篇换堆）。只有簇 55 / 54 五种子完全一致。

### 1.5 跨簇「同一事件」检测 ❌ 两条路都失败

尼泊尔洪灾在生产里同时落在簇 55 和 54（过分割）。想机械检测这类情况：

- **核心实体 Jaccard**（出现在 ≥25% 标题里的专有名词）：精度 **1/7**。`Nepal`（同一事件共享国名）
  与 `Trump`（不同事件共享人名）从实体本身分不开。加「作为核心实体出现在 ≥3 个簇即停用」也没滤掉。
- **簇质心余弦**：尼泊尔那对确实排第 1（0.980），但第 2 名是两个印度杂讯袋（0.977），中位数 0.944
  ——**区分度只有 0.003**。

**结论**：「过分割」方向目前没有可靠的零标注指标，只能靠金标里的已知事件做回归。

### 1.6 靠调 `eps` 同时治杂物袋和事件完整性 ❌ 一个旋钮两件对立的事

```
eps=0.35（生产）  50 簇   单源杂物袋 4 个/190 篇   洪灾 121/126 收在一个簇 ✅
eps=0.25          90 簇   单源杂物袋 5 个/138 篇   洪灾散在 7 个簇
eps=0.00         157 簇   单源杂物袋 0 个 ✅        洪灾散在 24 个簇、17 篇进噪声 ❌
                                                  跨种子 ARI 0.31（几乎不可复现）
```

## 二、成立的

### 2.1 杂物袋检测器（无标注，精度 96%）

**病灶**：一家媒体当日全部产出被整袋扫进一个簇。簇 29（89 篇、94% 来自 Times of India）里有
德里谋杀案、Raksha Bandhan 祝福语、RSS 访美、HDFC 银行 CEO 辞任、宝莱坞悼念会、南卡罗来纳枪击。
唯一共同点是同一个源。

**为什么 HDBSCAN 判不出来**：噪声看的是**密不密集**，而同源新闻因文风、人名地名、标题句式相似
在向量空间里天然抱团——**密度很高**。「噪声」是孤零零的文章，「杂物」是一堆彼此无关但写法相似的
文章，密度算法只看得见「像」。

**判据（两个信号必须并用）**：

```
篇数 ≥20  且  （实体共享 <0.30  或  单源占比 ≥0.8）
```

8 天 29 次 workflow / 98 个大簇上人读复核：命中 23 个，**22 真 1 误（精度 96%）**。
两个信号缺一不可——实体共享漏掉一个印度杂讯袋（`India` 反复出现把共享比例抬到 0.56），
单源占比漏掉 9 个多源题材袋（如 58 篇的环境特稿袋：9 个源、单源占比 0.52、实体共享 0.09）。

实现在 `apps/backend/prototypes/dedup-band/cluster-metrics.py`。

### 2.2 BISECT「只切第一刀」剥杂（窄条件下可靠）

一刀 k=2 bisecting k-means + BIC 判定是否接受。簇 55 上：事件完整率 102/102、纯度 93.6%、
碎片 1、零单篇组，38 篇港闻/中国杂讯整块剥掉、0 篇洪灾泄漏。

**但门要三条齐**（在 13 个大簇上恰好只放行该放行的 2 个）：

```
BIC 接受  且  5 个随机种子划分完全一致  且  两堆共享专有名词低
```

第三条是承重的：簇 2（挪威国王 29 篇）BIC 判 SPLIT 且 ΔBIC=+581，但切出来的是「新闻主线 vs
新王人物侧写」——同一件事的两个角度。两堆共享专有名词 0.286（全场最高）把它拦下了。
ΔBIC 的大小分不开它们（簇 54 的 Δ 只有 +354，比挪威还小）。

### 2.3 LLM 做成对判定很准

把切碎的 7 条洪灾主线原样问回同一个模型「这几条是不是同一个 happening」，一次答对
（`members: [1,2,3,4,5,6,7]`，判词 "They are one happening"，`finish_reason=stop`）。

**所以不是能力上限，是任务结构。** 模型在小任务上可靠、在大任务（一次划分上百条）上不可靠。

### 2.4 生产 `eps=0.35` 不是最优

金标读数见 `scripts/eval/clustering/README.md`。`eps=0.30` 在 B³-F1（0.930 vs 0.926）、纯度
（0.387 vs 0.324）、单篇被吞（6/7 vs 7/7）上全面更好，严格完整率只掉 0.002。
**定档前还差一个数据点：F2 窗口上的 `eps=0.30` 没跑过。**

## 三、为什么问题在特征不在算法

聚类吃的是 384 维 e5-small 句向量，**这是唯一的特征**。文章分析阶段早就为每篇算好并落库了
`key_entities` / `primary_location` / `event_summary_points` / `thematic_keywords`——**一个都没用**。

句向量编码的「像」包含**写法、体裁、地域用词**，所以：

- 印度时报当日国内新闻抱成一团（文风像）
- 挪威国王的「人物侧写体」自成一团（体裁像）
- 极端天气特稿抱成一团（题材像）

而杂物袋检测器之所以管用，恰恰是因为它用了**向量里没有的那一维**（标题里的专有名词）。这是
「缺失的特征确实有信息」的直接证据。

**对照业界**（详见 `cluster-to-story-segmentation.md`）：Story Forest / EventX 用 TF-IDF + 关键词
共现图 + 有监督 SVM；Event Registry 用 TF-IDF 系；BERTopic 用 embedding 聚类但簇的表示用 c-TF-IDF。
**没有一家拿单个通用句向量的余弦做事件聚类。**

> ⚠️ 注意：「纯 embedding 会把同源文风聚成假簇」这句是**从本轮数据推的**，文献里没有直接做过
> 这个实验。文献只能说明「主流不这么做」。

## 四、方法论教训

### 4.1 标题推理的错误率

用 R2 正文裁定了 17 条不确定项：**判对 14 条、判错 3 条**。三条错的共同点——
**都是「规则推出来的自信答案」**：

- Qusra 两条：用「行为主体不同（以军 vs 定居者）、相隔 36 小时」推出该拆 → 正文显示是同一场自
  8 月 9 日起的持续围困的两次升级，**该合**
- 两条「标题不自足」的：用「没锚点就不进」推出证据不足 → 正文明确指向本事件，**该收**

**规则本身没错，错在用规则替代证据。** 凡能取到正文的，读正文。

### 4.2 `unverifiable` 这一档的价值

它把「我不知道」显式记下来，所以后来能被正文裁掉。当初若硬判 in 或 out，这三条错误就永远埋在
金标里了。**区分「证据不足」与「信息指向别处」是必要的**，否则它会变成所有拿不准条目的垃圾桶。

### 4.3 指标必须成对，否则单向调参就能刷分

```
只看杂物袋率  → 把所有东西扔进噪声即可，进簇率会露馅
只看完整率    → 把所有东西堆成一大坨即可，纯度会露馅
只看单次读数  → 换个随机种子就变，稳定性会露馅
```

**稳定性是门不是分**：读数不可复现时，其他指标都不用看。本轮靠它当场淘汰了 BISECT 递归
（11/13 簇换种子换答案）和 Leiden（F2 上 ARI 0.387）。

### 4.4 建金标的流程（有效，可复用）

1. 三个标注者**各自通读全库**、各负责若干事件、互不通气
2. 协调者统一判据后，三组按同一把尺各自复核并翻案
3. 独立复核（另一个模型，read-only）专攻粒度一致性、跨组不一致、系统性偏差、漏标
4. 按复核结论**收紧**（全部降档，不删条目）
5. 用正文裁定全部存疑项

三个独立标注者在收紧判据后**各自翻案且方向互相吻合**（B 组「市长取消婚礼」翻回 members 时
自己写的理由是「对应 A 组假信息浪潮那一档」），这是判据可迁移的最好证据。

### 4.5 为什么这版金标不用 LLM 产参考划分

上一版（2026-06，见 `clustering-gold-construction.md`）用多次采样 + consensus 让 LLM 产参考划分。
**这一版改成人读**，因为下一步要评的是**特征工程**——若指标本身由文本特征算出，改特征就成了
自己评自己（加实体特征 → 按实体聚类 → 实体类指标必然变好，但不代表簇变对了）。
