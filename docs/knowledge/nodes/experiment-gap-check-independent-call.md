## 读数原文

`briefEvidence.ts:24-29`：

> 自检是独立任务，不是同一次调用里的约束。写作时模型在一大堆材料里做隐式取舍，
> 实测材料到位 11/14、三份稿全写只有 4/14——三分之二的材料白给。而 102 份成稿
> `finish_reason` 全是 stop、平均输出 458 token（上限 2500），**篇幅有余量**；
> 核心事件（≥6 篇报道）采纳率只有 38–56%，**也不是合理取舍**。
> 单独一次「找漏」调用的注意力分配跟「写一篇好稿」完全不同，不参与显著性竞争。
> 实测四簇：期望单份覆盖 41.1%（初稿）→ 51.9%（补漏后），增益 15 格、只丢 1 格。

commit 6128998 提交说明用『注意力分配跟"写一篇好稿"完全不同，不参与显著性竞争』
这句话概括了本条读数最核心的机制解释。

## 值得复用的方法：用 finish_reason + token 均值排除『合理取舍』这个替代解释

这条读数最值钱的不是『覆盖率从 41.1% 提到 51.9%』这个数字（数字绑定在这一版 prompt、
这一批四簇样本上，换 prompt 或换数据会变），而是**论证『取舍不合理』时用的排除法**：

面对『模型漏写了很多材料』这个观察，最自然的两个反驳是『可能是篇幅写不下』和『可能是
模型在做合理的编辑取舍，重要的都写了』。这两个反驳都可以被独立、廉价的信号直接检验，
不需要人工重新通读每一份成稿去猜模型的意图：

- **篇幅够不够，看 finish_reason 和 token 用量就够**：如果模型是被空间逼着漏写，
  应该看到大量 `finish_reason=length` 或输出逼近 token 上限；102 份成稿全部正常收尾
  且只用了不到两成的预算，直接排除了『写不下』这个解释，不需要猜。
- **是不是合理取舍，看『重要的事件有没有被优先写』**：如果模型在按重要性排序取舍，
  越重要（报道篇数越多）的事件采纳率应该越高；核心事件（≥6 篇报道）采纳率只有
  38–56%，说明写与不写跟事件本身的重要性没有对应关系，排除了『合理取舍』这个解释。

两个替代解释都被现成的、不需要额外标注的信号排除之后，剩下的解释——『写作时的注意力
分配本身就是不可靠的，需要一个独立的、专门检查覆盖的步骤』——才立得住。**这种『先用
低成本信号排除自然会被想到的替代解释，再接受更深的结论』的论证方式，本身比这批具体
数字更值得在其他场景复用**：任何观察到『模型输出遗漏了本该覆盖的内容』时，都可以先
问『是不是空间不够』『是不是在做合理筛选』，用现成的元数据（finish_reason、token 用量、
重要性排序）先排除掉这两条，而不是直接假设『需要加约束』或『需要加篇幅』。
