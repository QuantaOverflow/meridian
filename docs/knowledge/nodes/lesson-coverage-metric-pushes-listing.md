**发生了什么**:为了过「核心层覆盖 ≥2/3」,我把篇幅从 4–7 句加到 8–14 句,再加「必写」约束。
读数确实变好,但用户读后的判定是:原型像「结构化信息汇编」,生产那版虽然信息少却是「高管简报」,
他要后者。**两代优化朝着一条与读者价值相反的线在走。**

**还有一处我自己走偏**:我一度提议「只要求前 K 件事」来让简报变短——那是在删事实。
高管简报的短靠**往上综合**(一句归纳一组事实、只留一两个关键数字),不是少写几件事。

**尺本身也会偏向清单**:判官逐条判「这条事件写到没有」,概括写法容易被判漏
(c36 把「Perim 岛」写成「红海诸岛」被判没命中)。所以覆盖率在结构上偏袒枚举式写法。

**可操作**:
- 指标要拿读者价值校准一次,成本最低的方式是把两份成稿摆给用户读(几分钟,零成本),
  而不是跑更多轮。
- 通过线与 scorer 分开存放,目标变了只改通过线,历史读数不作废(已落实为 `policy.json`)。
