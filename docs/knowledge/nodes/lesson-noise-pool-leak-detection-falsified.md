## 想法与动机

ADR 0003 把聚类换成阈值型凝聚后，噪声池（未成簇的文章）占了约 65% 的输入。这个数字第一眼很吓人，
让人想问：这些文章里是不是藏着被漏掉的真实事件？生产环境没有金标，不可能靠人工核对，
所以想找一个**纯几何、不依赖标注**的检测器：在噪声池里再跑一遍同款聚类，如果又跑出一个
≥3 篇的组，就当作「疑似漏报事件」，报给运营去人工复核。

## 实测结果

在两窗金标上跑了这个检测器，精度只有 **0.05–0.33**，没有一个阈值同时给出可用精度与非零召回——
换句话说，报出来的「疑似漏报组」十有八九不是真事件。

## 为什么会这样

两个原因叠加：

1. **噪声池本身的构成决定了假阳性率必然高。** 65% 噪声里 81% 是本来就只有一篇报道的孤稿，
   噪声池实际上是 700 多篇互不相关的文章堆在一起。任何相似度阈值，只要扫描的候选组数量
   足够多，都能在纯随机的孤稿堆里偶然凑出满足「≥3 篇、彼此够相似」的候选组——这些组不对应
   任何真实事件，纯粹是几率碰撞。
2. **真信号极度稀疏。** 按 ≥3 篇口径，F1 只有 3 个事件、F2 只有 4 个事件真的被整簇漏掉。
   这么小的分子意味着任何精度估计的置信区间都很宽——宽到没法把某个阈值判定为「比另一个更好」，
   这不是「调参没调到位」，是**样本量不支持在这个问题上做阈值选择**。

## 处置

**不建议在生产上线这类检测器。** 已确认「均值掩盖分布」（ADR 0003 决定表里的完整率是全体
交付事件的均值，实际是 40 个 1.0 与 17 个被削两到五成的事件混在一起）以及「真损失集中在
≥3-4 篇边缘事件、≥5 篇零丢失」这两条更值得依赖的读数——它们不需要检测器就能从现有金标复跑
得到，而检测器想解决的是「生产没有金标怎么办」，但连有金标的窗口都测不出可用操作点，
没有理由指望它在没有金标的生产上表现更好。

## 对这条债的意义

如果确实需要生产环境的漏报监控，债的性质是**需要非几何的信号**（如人工抽样复核、或让 LLM
读噪声池里的候选组做语义判断，而不是靠余弦距离），这是新工作，不是调阈值能解决的——
与 [[lesson-cosine-cannot-detect-duplicate-events]] 里「归并阈值调不动」是同一类教训：
当分布本身不可分时，换阈值只是在同一条无效曲线上挪动，不会产生新信息。
