# gold/ —— 判官的人工标注

`gold/<axis>.json` 是某一轴的人工标注。它的唯一用途:量判官的真阳率 / 真阴率
(`node judge-alignment.mjs --axis=<axis> --run=out/<runId>`)。

**为什么非要有它**:2026-09-20 那轮三个临时判官在一天生产数据上判了 51 篇 / 248 句,报出 72 条旗标;
人工复核第二遍发现只有约 22% 是读者可见的错,其余是「出处挂错位置」被判成了编造 ——
判官的真阳率约 0.22,而当时没人知道。所以 CONTRACTS.md §5 写着:
**没与人工对齐过的判官,它报的比例只能当量级参考,不能进对比表。**

## 格式

```json
{
  "axis": "citation-support",
  "labels": [
    { "cluster": 3, "run": 1, "ref": "b1s3", "label": "fail", "note": "「首次」这个成分被引句里没有" }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `axis` | 轴名,必须与文件名一致(`judge-alignment.mjs` 会核) |
| `cluster` | 簇 id,对应 `out/<runId>/c<clusterId>.json` |
| `run` | 第几次重复(`run.json` 的 `epoch`)。标注挂在**某一稿**上,换一稿就不再是同一条句子 |
| `ref` | `b<块序号>s<句序号>`(都从 1 起);整篇一条的轴(`event-mixing`)写 `brief` |
| `label` | 只有 `pass` / `fail`。判不准的**不要写进金标** —— 拿不确定的标注去量判官,量的是两边的不确定 |
| `note` | 一句理由。分歧表会把它和判官的理由并排打出来给人复核,所以别省 |

`run` 可省;省了就对任何 epoch 都算数。`run.json` 里有 `epoch` 时 `judge-alignment.mjs`
自动按它筛 —— 悄悄跨 epoch 比对会把另一稿的标注算进来,而这不报错。

## 怎么标

1. 先挑样本:**别只挑判官报了旗标的句子**。只标旗标句就只能算出精度,算不出真阳率
   (漏报那一格永远是空的),而漏报恰恰是 `actor-swap` / `strength-distortion` 的主要失效。
   做法:随机抽一批句子标全,再补标判官报旗标的那些,两部分都记进同一个文件。
2. 标的时候读那一轴 `judges/<axis>.md` 的「判什么」和「你可以读什么」,**用同一套证据范围**。
   人看全簇、判官只看被引句,那量出来的分歧是范围差异,不是判官的偏差。
3. 分界那一条特别容易在人工这边也搞错:**事实在簇内别处有、只是不在被引句里 → `citation-support`
   的 `fail`,不是 `invented-fact` 的 `fail`。** 这正是上一轮 4 倍虚高的来源。
4. 标够 **30 条**再拿去比较臂。不足 30 条 `judge-alignment.mjs` 会打警告:
   置信区间比臂间差异还宽,这时的 TPR/TNR 只能当量级参考。

## 文件

- `<axis>.example.json` —— 格式样例,不参与任何计算(`judge-alignment.mjs` 只读 `<axis>.json`)。
- `practice-risk-v1/` —— 另一件事(练习集),与本目录的判官金标无关。

## citation-support：已对齐（2026-09-21）

`citation-support.json` —— **60 条，fail 31（52%）**。第一份真正可用的金标。

### 怎么标出来的

样本：v6 在 fixtures-r94 六个簇上三轮重复的 87 句，固定种子随机抽 60
（随机抽样不是形式——只标判官报旗标的句子算不出真阴率，见上文）。

三个不同模型各自独立标一遍，**互不可见**：

| 标注者 | 模型 | fail | 与最终裁决一致（18 条分歧内） |
|---|---|---|---|
| A | sonnet | 23 | 10/18 (56%) |
| B | haiku | 20 | **3/18 (17%)** |
| C | codex | 32 | **17/18 (94%)** |

18 条分歧全部人工裁决；再从 42 条三票一致里**随机抽 15 条人工复核**，未发现共盲
（只看分歧永远发现不了三个模型一起错的那类，见 memory `article-quality-judge-eval`）。

**haiku 不能当标注者也不能当判官**：18 条里只对 3 条，系统性过宽——限定词没被支撑、
因果被强加这类它一律放过。这个结论不依赖后面的对齐读数，单看这张表就成立。

### 判官对齐读数

判官 = `judges/citation-support.md`（`promptId` `f657f9cd6f4eaa26`）+ sonnet subagent。
判定归档在 `citation-support.judge-sonnet.json`。

```
TP 27   FP 0   TN 29   FN 4
真阳率 0.871   真阴率 1.000   精度 1.000   总一致率 0.933
```

**可以进对比表了**（CONTRACTS.md §5 的门槛：对齐过 + ≥30 条）。但带三条限界：

1. **漏报集中在「隐含关系」类。** 4 条漏报全是同一种病——因果被强加、动机被嫁接、
   语义方向相反（"面临质疑" vs "已有影响"）、代词归因（"it warned" 归给 Pentagon）。
   判官对**显式缺失**（数字、人名、地名没出现）抓得准，对**关系被悄悄加上**抓不到，
   而且四条都判 pass 且没写理由——它根本没意识到有争议。
   用这个判官时，隐含关系类要靠人工抽检补。
2. **精度与真阴率都是 1.000，别当真。** 60 条上出现两个满分，通常意味着样本不够难。
3. **sonnet 既是标注者 A 又是被测判官**，读数偏高；但它在 18 条分歧里只对 10 条、
   金标最终与它分歧 8 条，偏差有限。

### codex 不能用这份金标测

它 17/18 与裁决一致、且参与了那 42 条一致投票——拿它当判官对着这份金标打分，
等于对着自己的答案打分，准确率必然虚高。要测 codex，得另标一批它没参与的。

### 为什么没有继续把 0.871 往上推

改规格（补一条「把两件事写成因果/目的/回应时，被引句必须明说这个关系」）能治那 4 条漏报，
但要重跑判官、重测，而**金标只有 60 条，0.871 与 0.95 的置信区间重叠**——测不出差别。
先按现状用，漏报方向是保守的（不造假警报）。
