# scorer-recall 标注规范（自包含）

标 `(简报句, 对应情报报告) → 是不是事实错 + 错的形状`，产出 `labels.jsonl`。

原目录没有独立的 rubric 文件，类别定义散在 `eval/scorer-recall/README.md` 里。
2026-09-23 迁移时抽出来写成这份，让标签能被独立解释。

## 怎么标

在一批简报 block 的可判定候选句里**人工找出真实事实错**——不是注入题。
本批的规模：12 个 block、82 句可判定候选句、找出 15 条。

**为什么不用注入题**：同一份原始标注实测过，人工注入 60 条按 quantity / actor /
polarity / state / scope 配平之后，类别分布与自然错完全不同（actor 自然占 60%，
注入只占 20%），而且**占自然错 20% 的时序错在注入体系里连类别都没有**——
而它后果最重。注入题量出来的召回不代表真实召回。

## 五个类别

| category | 定义 | 本批条数 |
|---|---|---|
| **actor** | 施事 / 归属 / 角色 / 论元互换 | 9（60%） |
| **time** | 时序或时点错，含因果顺序倒置 | 3 |
| **quantity** | 数量、金额、比例写错 | 1 |
| **state** | 状态或结果写错（已发生 / 未发生、成功 / 失败） | 1 |
| **epistemic** | 确定性层级写错（声称被写成事实、推测被写成结论） | 1 |

**actor 类里最常见的具体形状**（9 条里占 6 条）：
两条各自正确的事实被融成一句，把 A 的谓语挂到 B 头上。
例：报告里「Joly 说了甲」与「Carney 说了乙」是分开的两行，
写作层融成一句并合并了主语，于是乙被挂到 Joly 名下。

这个形状注入题造不出来——它不是改一个词，是两句压缩时的结构性错位。

## 每条记什么

```json
{"id":1,"block":"c0-lead","category":"actor","layer":"写作层",
 "match":"<出错的原文片段，用于定位>",
 "why":"<错在哪，一句话>"}
```

- `layer`：错发生在哪一层（写作层 / 报告层），用于归因
- `match`：定位用，不是完整句子
- `why`：判据，也是复核依据

## 用法限制

这份是**消耗品**，不是长期资产：

- 证据（v3 写作层的产出正文）在 `apps/backend/prototypes/brief-v3-prod/out/raw/`，
  gitignored，原机之外无法重建。**召回率算不出来了。**
- 那一层已退役，新链路不产生同形态的输出。

留着的唯一用途：设计新判官时翻出来看真实错误长什么样，尤其 actor 那 9 条。
量化结论已蒸馏，见 `manifest.json` 的 `distilled`。
