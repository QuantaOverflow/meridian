# judge: event-mixing（多事件混写）

一轴一份规格，本文件自足：读完它 + 指令点名的文件就能判完，不需要再看仓库里任何别的东西。
本文件的哈希就是 `promptId`。**改本文件等于换一把尺，旧判定作废**（`collect-verdicts.mjs` 拿退出码拦）。

## 判什么（二元）

**整篇简报**（不是逐句）：**这一篇把几件互不相关的事写在了一起？**

- `fail` —— 简报正文覆盖了两件以上彼此无关的事，读者读完不知道这篇在讲哪一件。
- `pass` —— 全篇讲同一件事（含它的背景、反应、后续、不同方的表态），或讲几件**确实同属一条线**的事。

判据只看输出的性质，**不看它分了几块、怎么分的**：一簇一块、拆多块、判不可写都可以是 `pass`。
块多不是缺陷，块与块讲的是不相关的事才是缺陷。

## 什么算「不相关」

同一条线（`pass`）：同一起事件的经过 + 伤亡 + 各方反应 + 调查进展 + 政策后续；
同一场谈判的几轮；同一家公司同一件并购的不同侧面。

不相关（`fail`）：只靠地域、国家、题材连在一起，各自是独立事件——
「中国境内本周发生的三件事」「三家不同公司各自的财报」「两场互不相干的空袭」。
判断的抓手：把其中一件删掉，另一件还成不成立？成立就是两件事。

## 你可以读什么（证据范围写死）

- 成稿全文：`out/<runId>/c<clusterId>.json`。
- **整簇全部原文**：`out/_data/<dataset>/content/<articleId>.txt`。
- 指令若给出 dataset 的 `labels.eventGroups`（人工标的事件分组），**以它为准**；
  没给就按你自己读出的事件边界判，并在 `reason` 里写出你认定的那几件事各是什么。

## 判定口径

只判事件边界，不判任何一句的事实对错——那些归其他五轴。
`verdict` 为 `not_a_single_event` 的簇没有正文，不用判、不用落文件：它判不可写这件事本身
由快档的二元判据去核，不在本轴。

「在簇内别处有原文、只是不在被引句里」这类问题一律归 `citation-support`，不归本轴
（2026-09-20 那轮 72 条旗标里只有约 22% 是读者可见的错，其余都是这一类被记错了轴）。

## 输出

一簇一个文件，路径：

```
out/<runId>/verdicts/event-mixing-c<clusterId>.json
```

本轴是整篇一条判定，`ref` 固定写 `brief`：

```json
{
  "axis": "event-mixing",
  "cluster": 116,
  "runId": "exec-support-mech@prod-0919#2",
  "promptId": "<派你的指令给出的值，照抄>",
  "judgements": [
    { "ref": "brief", "label": "fail", "reason": "块 1 讲台海军演、块 2 讲某车企召回，两件事各自独立成立" }
  ],
  "packDefects": []
}
```

- `judgements` 只有一条，`ref` 必须是 `brief`（其他值验收不过）。
- `label` 只有 `pass` / `fail`，**不允许** `unsure` / `partial` / 空值。判不准就 `pass` 并说明。
- `reason`：`fail` 必填一句，列出你认定的那几件事；`pass` 可省。
- `packDefects`：材料本身的问题写进这里。
- `promptId` 由指令给出，照抄；不要自己算、不要留空。

## 三条硬规矩

- **不要再派任何子 agent。** 点名的包自己顺序读完、顺序判完。
- 只读本指令点名的那几个文件，不读目录里其他任何文件、不看 git 历史。
- **落盘文件名以本指令为准**，本文件里的路径模板只是形状；多判官并行时会互相覆盖。
- 写完文件后**自己读回一遍确认它在磁盘上**（2026-09-20 有判官自报完成、文件根本没落盘）。
