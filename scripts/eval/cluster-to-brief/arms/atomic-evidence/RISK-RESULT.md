# 两种风险核验原型：开发信号

2026-09-17。仅 c36 已知失败的八个聚焦样本；没有读 heldout，没有验证完整组合架构。

## 机制与预期

1. alignment：模型自行识别所有适用事实维度，每个维度返回断言片段、原文引用与支持状态。
2. specialist：每个样本给一个预先写好的窄问题，仅核验该风险点，同样必须返回原文片段。

两条路线均用 Workers AI glm-4.7-flash 作被测功能模块，不是远程 LLM judge。语义参考判定由当前 Codex 会话直接读冻结原文完成；它不是盲评或多人标注。

## 成本与契约

总共五次成功 HTTP 模型调用（包含两次 specialist 第一组的格式失败）：3,282 input tokens、4,542 output tokens，合计 91.02 秒；没有美元价格估算。
specialist 第一组两次返回的引用都添加了边界省略号。没有再次调用：仅删首尾省略号，且剩余文本确为原文子串时恢复；原始输出保存在 risk-calls.jsonl，恢复记录保存在结果文件。没有修改模型语义状态。
程序检查原文 quote 与 claimSpan 的精确子串，但这不等于 quote 足以蕴含断言；语义由 Codex 核对。

## 决策与未验证部分

- 不把“全维度自由展开”的 alignment 直接融合进现有 gate；更多检查可能增加假维度和误杀。
- 保留 specialist 的单问题接口和逐字证据锚点，作为下一轮候选机制；不以本轮八例升级为可部署核验器。
- 问题是人工给定且指向已知风险，尚未实现自动风险识别、问题完备性及多风险否决聚合。这可能是信号来源，而不只是判定器变强。
- invented-order 同时包含动作增强与错误时序，下一轮应使用 damaged 而非 shut 做纯时序对照。
- 下一步仅测试自动问题规划能否从未标注的候选产出必要风险问题，再复用 specialist；不要立刻扩大到 30/156 条模型调用。
