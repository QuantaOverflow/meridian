# judge: citation-support（出处支撑）

一轴一份规格，本文件自足：读完它 + 指令点名的文件就能判完，不需要再看仓库里任何别的东西。
本文件的哈希就是 `promptId`。**改本文件等于换一把尺，旧判定作废**（`collect-verdicts.mjs` 拿退出码拦）。

## 判什么（二元）

对成稿的每一句：**这句话声称的出处，那几句原句本身是否足以支撑这句话的全部成分？**

- `pass` —— 被引的那几句合起来，把这句话的每个成分都说到了（主体、动作、数字、时间、因果、程度词）。
- `fail` —— 有任何一个成分要靠被引句以外的材料才能补上。

不判这句话事实对不对（那是别的轴），只判**引的是不是该引的那句**。
一句话可以事实全对却引错句子（`fail`），也可以引对句子却写错了（本轴 `pass`，另一轴 `fail`）。
判完不要回头改。

## 你可以读什么（证据范围写死）

- 成稿：`out/<runId>/c<clusterId>.json`。
- **只有**该句 `sources[]` 列出的原句：每条 source 自带 `quote` 字段，就是那句的逐字原文（契约 §3 必填）。
  `quote` 缺失或与 `articleId`/`sentence` 对不上，记 `fail`，`reason` 里写「出处不可解析」。

**整簇其他文章、其他句子，本轴一律不得用来支撑。** 这一条是本轴的定义：
「这件事簇里别处有写」恰恰是 `fail` 的典型样子——出处挂错了位置，不是内容编造。

## 与 `invented-fact` 的分界（这一条写在这里是因为它曾造成 4 倍虚高）

> **某个事实在簇内别处有原文、只是不在被引的那句里 → 这是 `citation-support` 的 `fail`，
> 绝不是 `invented-fact`。**

2026-09-20 那轮三个临时判官报了 72 条旗标，复核只有约 22% 是读者可见的错，
其余全是「出处挂错位置」被判成了编造。本轴负责收下这一类，`invented-fact` 只管簇内哪儿都找不到的。
所以本轴 `fail` 率高是**正常的**，它不是质量警报，别去压它。

## 输出

一簇一个文件，路径：

```
out/<runId>/verdicts/citation-support-c<clusterId>.json
```

```json
{
  "axis": "citation-support",
  "cluster": 7,
  "runId": "exec-support-mech@prod-0919#2",
  "promptId": "<派你的指令给出的值，照抄>",
  "judgements": [
    { "ref": "b1s3", "label": "fail", "reason": "被引句只写了死亡数，没有「首次」这个成分" },
    { "ref": "b1s4", "label": "pass" }
  ],
  "packDefects": []
}
```

- `ref` = `b<块序号>s<句序号>`，两个序号都从 1 起，按成稿 `blocks[]` / `sentences[]` 的原顺序。
- `label` 只有 `pass` / `fail` 两个值，**不允许** `unsure` / `partial` / 空值。判不准就 `pass`
  并在 `reason` 里说明为什么判不准——宁可漏报，也别造一条假旗标。
- `reason`：`fail` 必填一句（缺了验收不过）；`pass` 可省。旗标必须可复核，这是上一轮的直接教训。
- `packDefects`：发现材料本身有问题（`quote` 与原文不符、成稿里泄漏了行内引用号、正文被截断……）
  就往这里写一条字符串。历史上 7 个判官有 6 个报出过真缺陷，这条不是客套。
- `promptId` 由指令给出，照抄；不要自己算、不要留空。值不对 `collect-verdicts.mjs` 会 exit 2。
- **每一句都要有一条判定**，一条不落。漏判会让分母被悄悄缩小，而缩小不报错。
  `verdict` 为 `not_a_single_event`（没有正文）的簇不用判，也不用落文件。

## 三条硬规矩

- **不要再派任何子 agent。** 点名的包自己顺序读完、顺序判完。
  （2026-09-19 实测：两个判官自行再派了子 agent，触发它的是「各判各的」这种措辞。）
- 只读本指令点名的那几个文件，不读目录里其他任何文件、不看 git 历史。
- **落盘文件名以本指令为准**，本文件里的路径模板只是形状；多判官并行时指令会给不同的名字，
  照模板写会互相覆盖（2026-09-19 四个判官里有一个这么覆盖过别人的结果）。
- 写完文件后**自己读回一遍确认它在磁盘上**。2026-09-20 有判官自报「完成」而文件根本没落盘，
  差点直接采用它报的比例。
