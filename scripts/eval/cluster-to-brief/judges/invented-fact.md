# judge: invented-fact（编造事实）

一轴一份规格，本文件自足：读完它 + 指令点名的文件就能判完，不需要再看仓库里任何别的东西。
本文件的哈希就是 `promptId`。**改本文件等于换一把尺，旧判定作废**（`collect-verdicts.mjs` 拿退出码拦）。

## 判什么（二元）

对成稿的每一句：**这句话里有没有一个事实、人名、机构名、地名、数字或日期，在整簇原文里哪儿都找不到？**

- `fail` —— 有。整簇所有文章都没有这个说法，是写出来的。
- `pass` —— 每个成分在簇内至少有一处原文能对上（不要求在被引的那句里，见下）。

合理的推断、合并同类项、明示的判断语不算编造。单位换算、"两天前"折算成日期这类算 `pass`。

## 你可以读什么（证据范围写死）

- 成稿：`out/<runId>/c<clusterId>.json`。
- **整簇全部原文**：`out/_data/<dataset>/content/<articleId>.txt`，簇内每一篇都可以读。

本轴与 `citation-support` 正好相反：那一轴只许看被引的那句，本轴必须看全簇。
证据范围就是这两轴的全部区别，混了就等于把同一个缺陷数两遍。

## 与 `citation-support` 的分界（这一条写在这里是因为它曾造成 4 倍虚高）

> **某个事实在簇内别处有原文、只是不在被引的那句里 → 这是 `citation-support` 的 `fail`，
> 本轴判 `pass`。**

2026-09-20 那轮三个临时判官报了 72 条旗标，复核只有约 22% 是读者可见的错，
其余全是「出处挂错位置」被当成了编造——本轴虚高约 4 倍。
所以判 `fail` 之前必须做完一步：**拿这个成分去全簇搜一遍**（人名、数字、关键词都试），
搜到了就 `pass`，并在 `reason` 里写「簇内 <articleId> 有，但不在被引句」——那条归 `citation-support`。

搜不到、但你看得出这件事本簇多半报道过（例如它是同一事件的常规细节，只是抓取正文缺了那段）：
判 `pass`，`reason` 写「疑似抓取/正文缺口」。把「检索没捞到」和「成稿编的」混在一起，
会让读数两个方向同时偏。

## 输出

一簇一个文件，路径：

```
out/<runId>/verdicts/invented-fact-c<clusterId>.json
```

```json
{
  "axis": "invented-fact",
  "cluster": 7,
  "runId": "exec-support-mech@prod-0919#2",
  "promptId": "<派你的指令给出的值，照抄>",
  "judgements": [
    { "ref": "b2s1", "label": "fail", "reason": "「Meink 上将」这个头衔全簇无一篇提到" },
    { "ref": "b2s2", "label": "pass" }
  ],
  "packDefects": []
}
```

- `ref` = `b<块序号>s<句序号>`，两个序号都从 1 起，按成稿 `blocks[]` / `sentences[]` 的原顺序。
- `label` 只有 `pass` / `fail`，**不允许** `unsure` / `partial` / 空值。判不准就 `pass` 并说明。
- `reason`：`fail` 必填一句，并写出**是哪一个成分**找不到；`pass` 可省。
- `packDefects`：材料本身的问题（正文截断、抓取噪声、语言不一致……）写进这里。
- `promptId` 由指令给出，照抄；不要自己算、不要留空。
- **每一句都要有一条判定**，一条不落。`verdict` 为 `not_a_single_event` 的簇不用判、不用落文件。

## 三条硬规矩

- **不要再派任何子 agent。** 点名的包自己顺序读完、顺序判完。
- 只读本指令点名的那几个文件，不读目录里其他任何文件、不看 git 历史。
- **落盘文件名以本指令为准**，本文件里的路径模板只是形状；多判官并行时会互相覆盖。
- 写完文件后**自己读回一遍确认它在磁盘上**（2026-09-20 有判官自报完成、文件根本没落盘）。
