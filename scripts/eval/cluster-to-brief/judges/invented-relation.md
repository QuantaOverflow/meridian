# judge: invented-relation（编造关系）

一轴一份规格，本文件自足：读完它 + 指令点名的文件就能判完，不需要再看仓库里任何别的东西。
本文件的哈希就是 `promptId`。**改本文件等于换一把尺，旧判定作废**（`collect-verdicts.mjs` 拿退出码拦）。

## 判什么（二元）

对成稿的每一句：**这句话把两件事连了起来（因果 / 时序 / 一致或对立 / 从属），而原文并没有这么说？**

`fail` 的典型形状——两个事实各自都有原文，**连接词是写出来的**：

- 因果：「因为 A，所以 B」「A 导致 B」「为回应 A 而 B」，原文只是并列提到 A 和 B。
- 时序：「A 之后 B」「A 期间 B」，原文没给先后，或先后正好相反。
- 一致/对立：「双方同意」「X 支持 Y 的说法」「作为反制」，原文只是各自表态。
- 从属：「B 是 A 的一部分」「同属一轮行动」，原文里 A、B 是两件独立的事。

`pass` —— 这个连接原文明确说了；或者这句话根本没建立关系（单一事实陈述）。
原文用了「in the wake of」「after」这类词，成稿写成同义的连接，算 `pass`。

## 你可以读什么（证据范围写死）

- 成稿：`out/<runId>/c<clusterId>.json`。
- **整簇全部原文**：`out/_data/<dataset>/content/<articleId>.txt`。关系是否存在，必须在全簇范围内找。

## 判定口径

只判**关系**，不判被连起来的两个事实本身对不对（那是 `invented-fact` / `strength-distortion`）。
两个事实都错、但原文确实说了这个关系 → 本轴 `pass`。

关系在簇内**别处**说了、只是不在被引的那句里 → 本轴 `pass`，那是 `citation-support` 的 `fail`：

> **在簇内别处有原文、只是不在被引句里的东西，一律归 `citation-support`，不归本轴。**
> 2026-09-20 那轮把这一类记成了编造，72 条旗标里只有约 22% 是读者可见的错，其余是出处挂错位置。

## 输出

一簇一个文件，路径：

```
out/<runId>/verdicts/invented-relation-c<clusterId>.json
```

```json
{
  "axis": "invented-relation",
  "cluster": 7,
  "runId": "exec-support-mech@prod-0919#2",
  "promptId": "<派你的指令给出的值，照抄>",
  "judgements": [
    { "ref": "b1s2", "label": "fail", "reason": "「为回应俄方试验」这个因果全簇无人给出，两篇只各自提到两件事" },
    { "ref": "b1s3", "label": "pass" }
  ],
  "packDefects": []
}
```

- `ref` = `b<块序号>s<句序号>`，两个序号都从 1 起，按成稿 `blocks[]` / `sentences[]` 的原顺序。
- `label` 只有 `pass` / `fail`，**不允许** `unsure` / `partial` / 空值。判不准就 `pass` 并说明。
- `reason`：`fail` 必填一句，写明**是哪一个连接**被编出来的；`pass` 可省。
- `packDefects`：材料本身的问题写进这里。
- `promptId` 由指令给出，照抄；不要自己算、不要留空。
- **每一句都要有一条判定**，一条不落。`verdict` 为 `not_a_single_event` 的簇不用判、不用落文件。
