# Clustering eval（聚类质量）

评 **RSS → 向量化 → HDBSCAN 聚类** 这一环：**同一件事的报道有没有聚在一起、不相干的有没有混进来。**

这条线此前**无尺**（2026-08-18 起金标归档，`metrics.ts` 一直空转）。2026-09-04 重建，形态与上一版
不同：上一版用 LLM 产参考划分，这一版是**人读金标**——因为要评的下一步是特征工程，若指标本身
由文本特征算出，改特征就会变成自己评自己。

打分全程**零 LLM、零网络**，0.15 秒跑完一组配置对照。

## 指标

### 两族，互补，都要看

```
B³-P / B³-R / B³-F1     只在金标覆盖到的文章上算 → 衡量「不同事件有没有被揉一起 / 一个事件有没有被拆散」
per-event 完整率 / 纯度   纯度分母是整个簇        → 衡量「簇里混进了多少金标外的东西」
```

**B-cubed 看不见杂讯**：它的 precision 只在交集上算，簇里混了多少未标注文章它不知道。而那恰恰是
这条管线的头号病。所以 per-event 纯度必须一起看。

### 两个口径

```
严格  只算 members            事件本身有没有被拆散
宽松  members + related       整条故事线有没有聚在一起
```

「洪灾引发的假信息 / 重建成本 / 电力贸易算不算同一件事」没有唯一答案，所以两个口径都报，不压成
一个数。**2026-09-04 实测：两者在 eps 0.10–0.35 全段读数一致**，即当前聚类器根本没做这个区分——
这个争议在数据上是空的。

### 四条样本资格规则

1. 单篇事件（7 个）完整率恒 1.0 → 不进宏平均；单独报「有没有被吞进大簇」
2. `exclude_from_primary` 的事件不进宏平均（Dolly Parton：讣告首报不在窗口内）
3. `duplicate_pairs`（同源同时刻重复入库）只计一次
4. `multi_label` 从纯度分母剔除——它确实属于该事件，算法放对了反而被扣分是错的

## 基线读数（2026-09-04）

UMAP(`n_components=5, n_neighbors=15, min_dist=0.1, cosine`) → HDBSCAN(`mcs=3, min_samples=1, euclidean`)，
只变 `cluster_selection_epsilon`，`random_state=42`：

| eps | B³-P | B³-R | B³-F1 | 严格完整 | 宽松完整 | 纯度 | 碎片 | 单篇被吞 |
|---|---|---|---|---|---|---|---|---|
| **0.35（生产）** | 0.863 | 1.000 | 0.926 | 1.000 | 1.000 | 0.324 | 1.00 | 7/7 |
| **0.30** | 0.889 | 0.975 | **0.930** | 0.998 | 0.998 | 0.387 | 1.06 | 6/7 |
| 0.25 | 0.890 | 0.812 | 0.849 | 0.985 | 0.986 | 0.398 | 1.18 | 6/7 |
| 0.20 | 0.924 | 0.608 | 0.733 | 0.953 | 0.953 | 0.508 | 1.65 | 6/7 |
| 0.10 | 0.948 | 0.521 | 0.673 | 0.874 | 0.875 | 0.576 | 2.35 | 6/7 |

**三条结论**：

1. **生产 `eps=0.35` 不是最优。** `0.30` 在 B³-F1、纯度、单篇被吞上全面更好，严格完整率只掉 0.002。
   定档前还差一个数据点：F2 窗口上的 `eps=0.30` 没跑过。
2. **纯度 0.324 意味着事件所在的簇平均比事件本身大三倍。** 多出来的两倍是混进去的东西。
   B³-P 只有 0.863 说明**连金标内部都在混**，不同事件被揉进同一簇。
3. **7 个单篇事件全部被吞进大簇**（四川地震、新加坡砍林、女子曲棍球决赛……），跨种子跨配置一致。
   这是之前所有指标都看不见的一类失败。

## 已知限制

- **只有一个窗口**。设计是「F1 调参、F2 验证」，F2 目前没有金标，验证那条腿是跛的。
- **只覆盖 26%**。三个标注者独立通读全库 + 独立复核确认这 24 个事件无漏成员，但不保证窗口里没有
  别的未标事件。对纯度是保守估计。
- **「单篇被吞」的阈值（纯度 < 0.2）是拍的**，未验证。当信号别当门。
- 其余偏差见 `rubric.md` 第四节，尤其**标题风格偏差**那条（换 fixture 必须重算）。

## 配套的无标注指标

金标精度高但只覆盖 26%。另有一套覆盖全库、精度较低的机械指标（杂物袋率 / 稳定性 / 进簇率），
在 `apps/backend/prototypes/dedup-band/cluster-metrics.py`。两套互补：

- **杂物袋率**：`≥20 篇的簇中，实体共享 <0.30 或 单源占比 ≥0.8` 的比例。8 天 29 次 workflow 上
  人读复核，精度 96%（22 真 1 误）。基线 23/98 簇。
- **稳定性**：同配置换 3 个随机种子的跨种子 ARI。**这是门不是分**——读数不可复现就别看其他指标。
  生产配置 F1 0.861 / F2 0.737。
- **进簇率**：防止靠「把难的全扔进噪声」刷分。生产 95.8%。
